## 三、怎么用这份教程（重要，别跳过）

### 每个知识点的学习循环

```
读讲解  →  敲代码  →  故意改错看错位  →  说出"一句话记住它"
 5 min     5 min         3 min               1 min
```

**"故意改错看错位"是整份教程里最值钱的动作。**
大多数人对 CSS 的恐惧来自"布局错位却不知道为啥"。
你把那个错位**亲手制造出来 20 次**之后，错位就变成了朋友——它是在提醒你"这条规则被违反了"。

教程里每一处坑都**给了可复现的 HTML+CSS**，不是口头描述。
所以你也可以自己复现：复制粘贴，看看是不是同一个错位。

### 三条铁律

1. **不要背属性。** CSS 的核心只有几个心智模型（盒模型、层叠、格式化上下文、Flex/Grid 的两根轴），其余全是查手册就能会的。
2. **不要一开始就上 UI 库。** 先把原生 Flex/Grid 写明白，再上 Tailwind（第 08 章），最后才是组件库。
3. **布局错位时，先问三个问题**：这是"一维"还是"二维"问题？我是在"声明关系"还是"手动摆位"？有没有更上层的格式化上下文在干扰？

教程里每个反例都标了 `/* ❌ */`，正确写法标了 `/* ✅ */`，建议你把两段都跑一遍对比。

## 六、先看三段代码，找找感觉

别怕看不懂，先感受一下"手动摆位"和"声明关系"的差别。

**第一段：同样是"三个卡片排一行"**

```css
/* 手动摆位（float 时代）：你在对每个卡片分别下命令，还要自己算间距 */
.card { float: left; width: 30%; margin-right: 5%; }
.card:last-child { margin-right: 0; }

/* 声明关系（Flex）：你告诉容器"孩子水平排列、首尾贴边、中间均分" */
.container { display: flex; justify-content: space-between; }
```

**第二段：同样是"水平垂直居中"**

```css
/* 借来的能力（绝对定位 + transform），写起来别扭 */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 为居中而生的能力（Grid 的 place-items） */
.parent { display: grid; place-items: center; }
```

**第三段：`flex: 1` 到底在干嘛**

```css
.item { flex: 1; }
/* 等价于 flex: 1 1 0% —— 长大比例 1、缩小比例 1、基准 0
   意思是"无视内容宽度，把剩余空间按 1:1 分给你"
   这就是"三个等宽列"的真相，而不是你以为的"都设成 33%" */
```

看出来了吗？
**CSS 布局不是"记住十几种写法"，而是"声明关系、让浏览器替你算"。**
理解了这一点，Flexbox、Grid、Tailwind 全都是它的推论。

剩下的都是细节。

## 七、承诺与免责

**这份教程保证：**

- 每个知识点都有可运行的 HTML+CSS，**全部在真实浏览器（Chrome/Edge/Firefox）上实测渲染**。
- 每处坑/错位现象都**给了可复现的代码**，你自己复制就能看到同一个错位，不是口头描述。
- 讲"为什么这么设计"，不只是"怎么写"。第 00 章讲了布局系统的演化史（`float`→Flexbox→Grid）。
- **Flex/Grid/响应式章节零第三方依赖**，只有 Tailwind 章按需引入（并明确标注版本）。

**这份教程不保证：**

- 让你成为像素级设计还原专家（那需要在真实设计稿里打磨）。
- 覆盖所有 CSS 属性（那需要查手册，而查手册是正常的工作方式）。
- 教你某个具体的 UI 组件库（Ant Design 等）。**本教程刻意不绑定组件库**，
  因为组件库会过期，而"声明关系、让浏览器算"这条规律不会。
