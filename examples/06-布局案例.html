第 06 章示例 · 十个布局案例：Flex vs Grid

下面每个案例都并排给出了 Flex 写法 和 Grid 写法 的真实渲染效果，以及各自的 CSS 代码。 注意观察 案例 3（卡片网格） 里 Flex 版最后一行被拉伸的现象——那就是"该用 Grid 却硬用 Flex"的代价。 推荐标签只代表"这个案例更适合用谁"，不代表另一种写法做不到。

案例 1 · 水平导航栏 推荐 Flex

一排内容驱动的链接。Flex 的 margin-left: auto 把「登录」推到右边；Grid 版要声明三列，还得给中间的链接组加 justify-self: center。

Flex 写法

Logo 首页 产品 关于 登录 
.nav { display: flex; align-items: center; gap: 12px; }
.nav .login { margin-left: auto; }

Grid 写法（能写，但绕）

Logo
首页产品关于
登录 
.nav { display: grid;
  grid-template-columns: auto 1fr auto; }
.nav .links { display: flex; justify-self: center; }

结论：用 Flex。 导航是一维 + 内容驱动。Grid 版那个 1fr 中间列是硬挤出来的，且链接组内部还得再套一层 Flex。

案例 2 · 垂直侧边栏 + 内容 推荐 Grid

页面骨架的两列结构。Grid 的 grid-template-columns: 90px 1fr 一眼看懂「左固定、右自适应」；Flex 版要加 flex-shrink: 0 防收缩。

Flex 写法

侧边栏
主内容
.layout { display: flex; height: 140px; }
.sidebar { width: 90px; flex-shrink: 0; }
.content { flex: 1; }

Grid 写法

侧边栏
主内容
.layout { display: grid;
  grid-template-columns: 90px 1fr;
  height: 140px; }

结论：用 Grid。 「两列骨架」是页面结构，Grid 把结构写在了脸上；Flex 版本多一个 flex-shrink: 0 补丁。

案例 3 · 卡片网格 推荐 Grid

5 张卡片、容器宽度固定。Flex 版（flex: 1 1 150px）最后一行只有 1 张卡片时会被拉伸占满整行（红色那张）；Grid 版（auto-fit）最后一行保持和上面一样的列宽。

Flex 写法（最后一行拉伸了）

4
5（被拉伸）
.cards { display: flex; flex-wrap: wrap; gap: 12px; }
.card { flex: 1 1 150px; }  /* ❌ 最后一行拉伸 */

Grid 写法（列宽严格一致）

1
2
3
4
5
.cards { display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(150px, 1fr));
  gap: 12px; }

结论：Grid 完胜。 卡片网格是二维 + 布局驱动。注意 Flex 版最后一行「5」比上面几张宽了一截——这就是 flex-grow: 1 的副作用。

案例 4 · 居中一个元素 两者皆可

单元素水平垂直居中。两行（Flex）和一行（Grid 的 place-items）效果完全一样，选谁看团队习惯。

Flex 写法

居中
.box { display: flex;
  align-items: center;
  justify-content: center; }

Grid 写法

居中
.box { display: grid;
  place-items: center; }

结论：两个都行。 居中太简单，两者都只是「顺手提供」。关键是一致——别在一个项目里两种混着写。Grid 的 place-items: center 是最短写法。

案例 5 · 页头页脚布局（sticky footer）推荐 Grid

页头、内容、页脚三行，内容区占满剩余高度、页脚贴底。Grid 的 grid-template-rows: auto 1fr auto 直接画出了三行结构。

Flex 写法

页头
内容（占满剩余）
页脚
.page { display: flex;
  flex-direction: column;
  min-height: 100vh; }
main { flex: 1; }

Grid 写法

页头
内容（占满剩余）
页脚
.page { display: grid;
  grid-template-rows: auto 1fr auto;
  min-height: 100vh; }

结论：用 Grid。 三行骨架是二维问题（同时控制「三行的存在」和「中间行的高度分配」），Grid 的三行模型更直白。

案例 6 · 圣杯 / 双飞翼布局 推荐 Grid

三栏：左右固定、中间自适应，且 HTML 里主内容排第一（SEO 友好）。Grid 用 grid-column 把「位置」和「文档顺序」解耦；Flex 只能用 order 改视觉顺序，会破坏键盘焦点顺序。

Flex 写法（order 改顺序）

主内容
左栏
右栏
.grail { display: flex; }
.main { flex: 1; order: 2; }
.left { width: 70px; order: 1; }
.right { width: 70px; order: 3; }

Grid 写法（HTML 顺序不动）

主内容
左栏
右栏
.grail { display: grid;
  grid-template-columns: 70px 1fr 70px; }
.main { grid-column: 2; }
.left { grid-column: 1; }
.right { grid-column: 3; }

结论：Grid 完胜。 「内容优先 + 视觉居中」本质是「位置与顺序解耦」，这是 Grid 的强项。Flex 的 order 不改 DOM 顺序，Tab 键仍先到左栏。

案例 7 · 堆叠式表单 推荐 Flex

一列往下排的线性流程。Flex 的 flex-direction: column 正好表达「一条线」；Grid 版单列是「用网格描述一个没有网格的结构」。

Flex 写法

.form { display: flex;
  flex-direction: column;
  gap: 8px; }

Grid 写法（能写，但没必要）

.form { display: grid;
  gap: 8px; }  /* 单列 Grid */

结论：用 Flex。 堆叠表单是「一条线」，不是「一张网」。只有「标签在左、输入在右」的两列对齐表单，才轮到 Grid。

案例 8 · 工具栏（按钮组）推荐 Flex

一排按钮，左边一组（格式）、右边一组（撤销/重做）。Flex 的 margin-left: auto 把第二组推右，按钮数量怎么变都对；Grid 版写死了 6 列，加一个按钮就坏。

Flex 写法

.toolbar { display: flex; gap: 12px; }
.group { display: flex; gap: 4px; }
.group:last-child { margin-left: auto; }

Grid 写法（写死列数）

.toolbar { display: grid;
  grid-template-columns:
    auto auto auto 1fr auto auto; }

结论：用 Flex。 工具栏是「一排数量不定的按钮」，内容驱动。Grid 要求预先声明列数，按钮一多就得改 grid-template-columns。

案例 9 · 画廊（瀑布流）两个都不擅长

瀑布流要求「每列独立向下堆叠、下一张塞到最短的列」。纯 CSS 的诚实答案是 columns（代价是纵向阅读顺序）；Grid 只能「近似」（需手动算每张 span 几行）；Flex 直接出局。

columns 版（真瀑布流）

1
2
3
4
5
.masonry { columns: 3; column-gap: 10px; }
.tile { break-inside: avoid; }

Grid 版（近似，需算 span）

1
2
3
4
5
.masonry { display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-auto-rows: 20px; gap: 10px; }
.tile:nth-child(1) { grid-row: span 3; }
/* ...每张都要算 span 几行 */

结论：都不完美。 注意 columns 版是「先从上到下再从左到右」的纵向阅读顺序；Grid 版保持了横向顺序，但要手动算每张卡片 span 几行（真实图片高度需 JS 量）。
