## 一、高频面试题（Q1~Q50）

### 1. Flexbox（10 题）

**Q1: `flex: 1` 和 `flex: auto` 有什么区别？**

**答：** `flex: 1` 展开是 `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`；`flex: auto` 展开是 `1 1 auto`。区别全在 `flex-basis`：`0%` 表示"先把内容宽度清零，再按比例分剩余空间"，所以 `flex: 1` 能让多个子项**严格等宽**；`auto` 表示"先保留内容自身宽度，再分剩余空间"，所以子项宽窄由内容决定。

- 关键区分：**`flex-basis: 0` vs `flex-basis: auto`**
- 等宽用 `flex: 1`，不等宽用 `flex: auto`

**Q2: `flex` 这个缩写到底包含哪三个值？分别是什么意思？**

**答：** `flex: <grow> <shrink> <basis>`。`flex-grow`：有剩余空间时按比例放大（默认 0）；`flex-shrink`：空间不足时按比例收缩（默认 1）；`flex-basis`：分配剩余空间之前的**基础尺寸**（默认 `auto`，即内容宽度）。三个值连起来描述了一个完整的"先定基础、再伸缩"的算法。

- 记忆：**grow 分剩余的，shrink 扛不足的，basis 是起跑线**

**Q3: `flex-grow` 的计算过程是怎样的？**

**答：** 先算出**剩余空间** = 容器宽度 − 所有子项的 `flex-basis` 之和；再把剩余空间按各子项 `flex-grow` 的**比例**分掉。两个容易记错的地方：(1) 它分的是"剩余空间"，不是"容器宽度"；(2) 基础宽度默认来自内容（`basis: auto`），所以"都设 `flex-grow: 1` 就等宽"是错的——内容不一样，起跑线就不一样。

```css
/* 容器 600px，三个子项各 100px，剩余 300px */
.a { flex-grow: 1; }  /* 100 + 300*1/3 = 200px */
.b { flex-grow: 2; }  /* 100 + 300*2/3 = 300px */
.c { }                /* 保持 100px */
```

- 一句话：**按比例分剩余，不是按比例分整行**

**Q4: `justify-content` 和 `align-items` 分别管什么？**

**答：** `justify-content` 管**主轴**（默认水平），`align-items` 管**交叉轴**（默认垂直）。主轴方向由 `flex-direction` 决定：`row` 时主轴是水平、交叉轴是垂直；`column` 时正好反过来。所以"水平居中"用 `justify-content: center`，"垂直居中"用 `align-items: center`——前提是默认的 `row`。

- 关键区分：**主轴 vs 交叉轴，不是"水平 vs 垂直"**（方向会随 `flex-direction` 变）

**Q5: 子项设了 `width: 200px`，为什么会被压扁？**

**答：** 因为 `flex-shrink` 默认是 `1`，空间不足时子项**允许收缩**，你写的 `width` 只是一个"希望值"，不是硬约束。想让它不被压扁，要加 `flex-shrink: 0`；或者用 `min-width` 设一个底线。反过来，`flex-grow` 默认是 0，所以子项不会自动撑满——这也是为什么"想让它填满要显式写 `flex: 1`"。

- 一句话：**`width` 是愿望，`flex-shrink` 才是硬约束**

**Q6: `flex-wrap: wrap` 之后，怎么控制换行后的行对齐？**

**答：** 用 `align-content`。当子项**换行成多行**后，`align-items` 只管"每一行内部"的对齐，`align-content` 才管"多行之间"在交叉轴上的分布（类似 `justify-content` 对单行主轴的分布，只是作用在交叉轴上）。常用值：`flex-start`/`flex-end`/`center`/`space-between`/`stretch`。前提是容器在交叉轴方向有额外空间（比如有固定高度）。

- 关键区分：**`align-items` 管行内，`align-content` 管行间**（仅多行时 `align-content` 才有效）

**Q7: `gap` 在 Flex 里和 `margin` 有什么区别？**

**答：** `gap` 是 Flex/Grid 容器原生的间距属性，只作用于**相邻子项之间**，首尾不留空隙，也不用处理"最后一个元素的 margin 要去掉"这种脏活。`margin` 是元素自己的属性，相邻会叠加、还会有外边距合并的问题。现代布局里，子项之间的间距优先用 `gap`，干净且不会出现"最后一格多出空白"。

- 一句话：**间距是"容器的事"，用 `gap`；不要用子项的 `margin` 去凑**

**Q8: `align-self` 是干什么的？**

**答：** 它覆盖**单个子项**在交叉轴上的 `align-items`，让某个子项"单独"采用不同的对齐。比如父级 `align-items: center`，但某个元素想贴底，就给它 `align-self: flex-end`。它只影响自己，不影响其他兄弟。

- 一句话：**`align-items` 的"单点覆盖版"**

**Q9: 怎么实现"一个元素在最左、其余都在最右"的导航栏？**

**答：** 两种经典写法：(1) 容器 `display: flex; justify-content: space-between`，把左、右两组分别包起来；(2) 容器 `display: flex`，给右边的元素/组设 `margin-left: auto`——`auto` 的 margin 会吸收所有剩余空间，把它推到最右。后者更常用，因为它不要求"刚好两组"。

```css
.nav { display: flex; align-items: center; }
.nav .logo { font-weight: bold; }
.nav .menu { margin-left: auto; }   /* 吸收剩余空间，推到最右 */
```

- 关键点：**`margin: auto` 在 Flex 里会吃掉剩余空间**，这是最常用的"推挤"技巧

**Q10: `display: inline-flex` 和 `display: flex` 有什么区别？**

**答：** `flex` 让容器成为**块级**的 flex 容器（独占一行），`inline-flex` 让容器成为**行内级**的 flex 容器（可以和文字、其他行内元素排在一行）。内部子项的布局行为完全一样，区别只在容器自己对外"像块还是像行内元素"。

- 一句话：**对内一样，对外一个是块、一个是行内**

### 2. Grid（8 题）

**Q11: `fr` 单位是什么？和 `%`、`auto` 有什么区别？**

**答：** `fr` 是"剩余空间的比例单位"。`1fr 2fr` 表示把容器里"扣掉固定尺寸之后剩下的空间"按 1:2 分配。和 `%` 的区别：`%` 相对的是容器总宽度，写 `50% 50%` 加个 `gap` 就溢出了；`fr` 会自动扣除 `gap` 再分。和 `auto` 的区别：`auto` 按内容大小定宽，`fr` 主动抢占剩余空间。

- 一句话：**`fr` 分的是"剩下的"，所以配合 `gap` 不会溢出**

**Q12: `1fr 1fr 1fr` 为什么有时候三列不等宽？**

**答：** 因为 `fr` 的最小尺寸默认是 `auto`（内容的最小宽度 `min-content`）。某一列放进一个超长单词或长 URL，它的 `min-content` 很大，`1fr` 无法把它压缩到等分，那一列就被撑宽了。解决：用 `minmax(0, 1fr)` 把最小尺寸压成 0，或给子项加 `min-width: 0`。

```css
.grid { grid-template-columns: 1fr 1fr 1fr; }                 /* 可能不等分 */
.grid { grid-template-columns: repeat(3, minmax(0, 1fr)); }   /* 严格等分 */
```

- 这是 Grid 里最高频的坑之一，务必会讲 `minmax(0, 1fr)`

**Q13: `grid-template-areas` 怎么用？有什么限制？**

**答：** 用一串字符串拼出一张"布局地图"，每个字符串是一行，字符串里用空格分隔列，用 `.` 表示空位。示例：`"header header" "sidebar main"`。限制：每行的**列数必须一致**，否则整条规则失效；要配合 `grid-template-columns`/`rows` 定尺寸，并用 `grid-area` 把子项对应到区域名。

```css
.layout {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main";
}
.header { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main { grid-area: main; }
```

- 核心价值：**布局结构一眼可读**，改布局只动"地图"不动 HTML

**Q14: `grid-column: 1 / 3` 里的数字是什么意思？**

**答：** 数字是**网格线的编号**，不是列数。`1 / 3` 表示"从第 1 条网格线到第 3 条网格线"，所以横跨的是**第 1、2 两列**。一个 3 列网格有 4 条竖线（编号 1~4），`span 2` 等价于"跨两列"的另一种写法。新手最容易把 `/ 3` 理解成"跨 3 列"，其实是"到第 3 条线为止"。

```css
.a { grid-column: 1 / 3; }   /* 跨第 1、2 列 */
.a { grid-column: span 2; }  /* 等价：跨 2 列 */
.a { grid-column: 1 / -1; }  /* 跨到最后 */
```

- 一句话：**线编号，不是列数**；`1 / -1` 表示跨到最后

**Q15: `repeat()` 和 `minmax()` 怎么用？**

**答：** `repeat(3, 1fr)` 等价于 `1fr 1fr 1fr`，用来省写重复的轨道；`repeat(auto-fill, minmax(200px, 1fr))` 是"响应式卡片墙"的经典配方——每列最小 200px、最大 1fr，`auto-fill` 自动算出"能塞几列塞几列"。`minmax(min, max)` 给轨道设一个最小值和最大值，配合 `fr` 或 `auto` 使用。

```css
/* 一行实现自适应卡片网格，无需媒体查询 */
.grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); gap: 16px; }
```

- 经典组合：**`repeat(auto-fill, minmax(200px, 1fr))` 一行实现自适应网格**

**Q16: `justify-items` / `align-items` / `place-items` 在 Grid 里管什么？**

**答：** 它们控制**子项在各自单元格内**的对齐。`justify-items` 管水平（行轴），`align-items` 管垂直（列轴），`place-items` 是两者的缩写（`place-items: center` = 两个都居中）。对应到"子项自己覆盖"的是 `justify-self`/`align-self`/`place-self`。注意：`justify-content`/`align-content` 管的是**整组轨道在容器里的分布**，别和 `-items` 搞混。

- 关键区分：**`-items` 管格子里，`-content` 管整片网格**

**Q17: Grid 和 Flex 各自的适用场景，举个例子？**

**答：** Grid 适合**二维骨架**——页面整体的"头部/侧栏/主区/底部"这种行列交错的布局；Flex 适合**一维排列**——导航栏里的一排按钮、卡片内部的一排标签。实际项目里两者常**嵌套**：外层用 Grid 定页面骨架，每个格子内部再用 Flex 排细节。选择标准就一句：**你脑子里想的是"行和列"就用 Grid，想的是"一排/一列"就用 Flex。**

- 一句话：**Grid 定骨架，Flex 排细节**

**Q18: `subgrid` 是什么？解决什么问题？**

**答：** `subgrid` 让**子网格继承父网格的轨道线**，这样嵌套的网格就能和父网格的行列对齐，而不是各算各的。它解决的是"多层嵌套时，内部元素无法对齐外层网格线"的问题。典型场景：一列卡片，每张卡片的标题、正文、按钮要**跨卡片水平对齐**——普通 Grid 做不到，`subgrid` 让子项共享父级的列线就能对齐。

- 加分点：知道它"继承父网格轨道"，能举"多卡片内容对齐"的例子

### 3. 盒模型与层叠（9 题）

**Q19: 盒模型是什么？`content-box` 和 `border-box` 的区别？**

**答：** 盒模型 = `content`（内容）+ `padding`（内边距）+ `border`（边框）+ `margin`（外边距）。`content-box`（默认）下 `width` 只指内容区，总宽 = `width + padding + border`；`border-box` 下 `width` 就是总宽，`padding`/`border` 从里面扣。`border-box` 更符合直觉，所以现代工程都统一 `* { box-sizing: border-box }`。

```css
/* content-box: width 100px，总宽 = 100 + 2*10 + 2*5 = 130px */
/* border-box:  width 100px，总宽 = 100px，内容区 = 70px */
* { box-sizing: border-box; }
```

- 一句话：**`border-box` = 所见即所得**

**Q20: `margin` 会合并（collapsing）是怎么回事？**

**答：** 垂直方向上，两个相邻块级元素的 `margin` 会**合并成较大值**而不是相加；父子之间也会合并（父无 `border`/`padding`/BFC 隔离时）。水平方向不合并。这是规范有意设计的，避免段落间距翻倍。绕过方式：一侧设 `margin`、用 `padding`、触发 BFC、或用 Flex/Grid 的 `gap`（没有合并这回事）。

```css
.a { margin-bottom: 20px; }
.b { margin-top: 30px; }   /* 间距是 30px，不是 50px */
/* 绕开：改用 flex 的 gap */
.box { display: flex; flex-direction: column; gap: 50px; }
```

- 记住三个关键词：**垂直、相邻、取大值**

**Q21: BFC 是什么？有哪些用途？**

**答：** BFC（Block Formatting Context，块级格式化上下文）是一个独立的渲染区域，内部布局不影响外部。用途：(1) 清除浮动、解决父容器高度塌陷；(2) 阻止父子外边距合并；(3) 隔离浮动，防止浮动元素覆盖进来。触发方式：`overflow: hidden`、`display: flow-root`、`float`、绝对定位等。其中 `display: flow-root` 是"纯粹为触发 BFC 而生"的现代写法。

- 一句话：**BFC 是一堵"隔断"，把内部的浮动和 margin 关在里面**

**Q22: 清除浮动有哪些方法？哪个最好？**

**答：** 传统有：(1) 给父容器加 `clearfix`（伪元素 `::after` + `clear: both`）；(2) 父容器 `overflow: hidden` 触发 BFC；(3) 父容器 `display: flow-root`（最语义化、无副作用）。但最根本的答案是：**现代布局直接用 Flex/Grid，根本不需要清浮动**——浮动只在"图文环绕"这种它本来的用途里才用。

- 加分点：能说出"清浮动是 `float` 布局时代的补丁，现代布局已不需要"

**Q23: `z-index` 什么时候不生效？**

**答：** 两种常见情况：(1) 元素 `position: static`（没定位），`z-index` 被忽略；(2) 元素所在的**层叠上下文**不同——`z-index` 只在同一层叠上下文里比较，父级一旦创建了层叠上下文（`opacity`/`transform`/`filter` 等），子元素再大的 `z-index` 也盖不过外层兄弟。另外 flex/grid 容器的直接子项即使 `static` 也能用 `z-index`，这是个例外。

```css
.modal { z-index: 9999; }            /* ❌ 没定位，被忽略 */
.modal { position: relative; z-index: 9999; }  /* ✅ 生效 */
.parent { transform: scale(1); }     /* ⚠️ 父级开了层叠上下文，子元素 z-index 被锁 */
```

- 排查顺序：**先看有没有定位，再看有没有被父级的层叠上下文锁住**

**Q24: 什么是层叠上下文？什么属性会意外创建它？**

**答：** 层叠上下文是一个"让元素在 z 轴上独立排序"的盒子，内部元素的 `z-index` 只在盒内比较。意外创建它的属性：`position` + 非 `auto` 的 `z-index`、`opacity < 1`、`transform`、`filter`、`perspective`、`will-change: transform` 等。最常见的坑：给父级加个 `opacity` 做动画，结果里面弹窗的 `z-index: 9999` 突然不管用了。

- 一句话：**`opacity`/`transform` 会悄悄开一个层叠上下文，把你的 `z-index` 锁进去**

**Q25: `position` 的五个值分别是什么？分别相对谁定位？**

**答：** `static`（默认，文档流正常排）；`relative`（相对**自身原本位置**偏移，仍占位）；`absolute`（相对**最近的定位祖先**，脱离文档流）；`fixed`（相对**视口**，脱离文档流）；`sticky`（相对/固定的混合，滚动过阈值后固定）。最容易记错的是 `absolute`——它相对的是"最近的 `position` 不为 `static` 的祖先"，不是视口。

- 一句话：**`absolute` 找祖先，`fixed` 找视口**

**Q26: `sticky` 的定位机制是什么？为什么不粘？**

**答：** `sticky` 在滚动到阈值（`top`/`bottom` 等）之前表现像 `relative`，超过阈值后像 `fixed` 粘住。但它受**父容器边界**限制——父容器滚出视口，sticky 元素也被带走。常见"不粘"的原因：(1) 忘了写 `top`；(2) 某个祖先设置了 `overflow: hidden/scroll/auto`，滚动的不是视口而是那个容器，sticky 相对它生效却看起来"不粘"；(3) 父容器高度不够。

```css
.nav { position: sticky; top: 0; }   /* 两个条件缺一不可 */
```

- 一句话：**`sticky` 需要 `top` 阈值 + 父容器不能截断滚动**

**Q27: 元素的宽高用 `width/height` 和 `min/max-width/height` 有什么区别？**

**答：** `width/height` 是"目标值"；`min/max-width/height` 是"约束边界"。实际渲染结果 = `clamp(min, width, max)`。这组属性在响应式里非常有用——比如 `width: 100%; max-width: 600px` 让元素"尽量宽但不超过 600px"，配合 `margin: auto` 就是经典的"容器自适应 + 居中"。

- 一句话：**`width` 是目标，`min/max` 是护栏**

### 4. 响应式（8 题）

**Q28: 什么是移动优先（Mobile First）？为什么推荐？**

**答：** 移动优先 = 基础样式按最小屏幕写，再用 `min-width` 断点**从小到大**逐步增强。原因：(1) 移动端内容更精简，先写移动端等于先想清楚"什么最核心"；(2) `min-width` 的覆盖顺序是"从小到大、逐层叠加"，逻辑直观、不易漏；(3) 移动端用户占比高、网络差，把"最简样式"作为默认也有性能好处。

- 一句话：**默认最简，逐级增强**

**Q29: `min-width` 和 `max-width` 的媒体查询有什么区别？**

**答：** `@media (min-width: 768px)` 表示"宽度 ≥ 768px 时生效"（从小到大，移动优先）；`@media (max-width: 768px)` 表示"宽度 ≤ 768px 时生效"（从大到小，桌面优先）。移动优先用 `min-width`，桌面优先用 `max-width`。两者本质等价，但 `min-width` 更符合"渐进增强"的推荐思路。

- 记住：**`min-width` 是"至少"，`max-width` 是"最多"**

**Q30: 断点（breakpoint）怎么选？有什么经验值？**

**答：** 断点应基于**内容什么时候"挤了/崩了"**来决定，而不是死记设备宽度。常见的经验值：`576px`（大手机横屏）、`768px`（平板）、`992px`（小笔记本）、`1200px`（桌面）。但这些只是起点——真正好的断点是"把窗口慢慢拉窄，看布局在哪一步开始变难看，就在那里断"。Tailwind 默认的 `sm/md/lg/xl/2xl` 也大致对应这几个档。

```css
@media (min-width: 768px) { ... }    /* 平板上：md */
@media (min-width: 1024px) { ... }   /* 桌面上：lg */
```

- 一句话：**断点跟着内容走，不跟着设备清单走**

**Q31: 什么是容器查询（Container Queries）？它和媒体查询的区别？**

**答：** 媒体查询响应的是**视口宽度**，容器查询响应的是**某个容器的宽度**。容器查询让"组件"能自我感知所在容器的空间，实现真正的组件级响应：同一个卡片，放进宽的主栏是横排，放进窄的侧栏就变竖排，不用关心整个页面多宽。它解决了媒体查询最大的局限——组件无法脱离"整页宽度"独立适配。

- 一句话：**媒体查询问"页面多宽"，容器查询问"我这块多宽"**

**Q32: 响应式布局常用哪些现代工具？**

**答：** 不用媒体查询就能响应的工具：(1) Flexbox 的 `flex-wrap` / `flex-grow`；(2) Grid 的 `repeat(auto-fill, minmax(200px, 1fr))`；(3) `clamp()` 让字号/尺寸平滑缩放（如 `font-size: clamp(1rem, 2vw, 2rem)`）；(4) 百分比 + `max-width`。需要"换布局结构"时才用媒体查询或容器查询。原则：**能用流体布局解决的，就别急着上断点。**

- 一句话：**先流体、后断点**

**Q33: `clamp()` 函数是什么？怎么用？**

**答：** `clamp(min, preferred, max)` 返回"夹在 min 和 max 之间、优先取 preferred"的值。典型用法是响应式字号：`font-size: clamp(1rem, 2vw + 0.5rem, 2rem)`，让它随视口平滑缩放、又不小于最小值、不超过最大值。配合 `vw` 就能实现"无断点的流式排版"。

```css
h1 { font-size: clamp(1.5rem, 4vw, 3rem); }   /* 最小 1.5rem，最大 3rem，中间随视口 */
```

- 一句话：**`clamp` = 带上下限的弹性值**

**Q34: 移动端 1px 边框、适配等问题，常用什么方案？**

**答：** 通常用 `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 让移动端按物理逻辑宽度渲染；配合 `rem` 做缩放、或直接靠响应式断点。真要谈"适配不同尺寸"的核心是：**布局用流体（Flex/Grid/clamp），间距和字号用相对单位（`rem`/`vw`），只在结构需要时用断点。** 避免为了"还原某个机型"写一堆 `max-width` 特判。

- 加分点：能说出"viewport meta"的作用，以及"不要为单个机型写特判"

**Q35: 图片/视频等媒体怎么做响应式？**

**答：** 三个层面：(1) CSS 层面，`img { max-width: 100%; height: auto; }` 让图片不超过容器宽度、按比例缩放；(2) HTML 层面，用 `srcset` + `sizes` 让浏览器按屏幕/DPR 选合适分辨率的图片；(3) 内容层面，用 `aspect-ratio` 或 `object-fit: cover` 控制裁切比例，避免图片撑破布局。现代还常用 `<picture>` 做艺术指导（不同断点用不同构图）。

```css
img { max-width: 100%; height: auto; }        /* 底线 */
.thumb { aspect-ratio: 16 / 9; object-fit: cover; }  /* 固定比例裁切 */
```

- 一句话：**`max-width: 100%` 是底线，`srcset` 是进阶**

### 5. Tailwind（7 题）

**Q36: Tailwind 的"原子类"是什么思路？**

**答：** 原子类（utility-first）= 每个 class 只做一件事（`p-4` 只管 padding、`flex` 只开 flex），通过**组合**多个 class 来表达一个元素的完整样式。它把"写 CSS"变成"在 HTML 里组合设计令牌"，好处是样式本地化、无命名负担、改一个元素只动一处；代价是 HTML 的 `class` 变长。

- 一句话：**把 CSS 拆成乐高积木，在 HTML 里拼**

**Q37: Tailwind 相比传统语义化 CSS（如 `.card`）的优劣？**

**答：** 原子类优势：开发快、零命名、样式不会全局污染、删代码不用找散落的 CSS。劣势：HTML 冗长、团队要背类名、样式复用靠"抽组件"而不是"抽类"。语义类优势：语义清晰、一个类承载完整外观。两者不是对错，是"分离粒度"不同——Tailwind 按"设计令牌"分离，传统按"组件语义"分离。工程上常用策略：**语义组件 + 内部原子类**结合。

- 加分点：说出"Tailwind 把分离维度从文件换成了设计令牌"

**Q38: Tailwind 的 `flex-1`、`flex-auto`、`flex-none` 分别对应什么？**

**答：** 对应 CSS 的 `flex` 缩写：`flex-1` → `flex: 1 1 0%`（等宽伸缩）；`flex-auto` → `flex: 1 1 auto`（先内容后伸缩）；`flex-none` → `flex: none`（即 `0 0 auto`，不伸缩、保持内容宽）。它们是 Tailwind 对 `flex` 三种常用形态的封装。

- 一句话：**`flex-1` 等宽、`flex-auto` 按内容、`flex-none` 定死**

**Q39: Tailwind 怎么实现响应式？移动优先体现在哪？**

**答：** 通过前缀断点类，如 `md:flex`、`lg:grid-cols-3`，它们默认是 `min-width` 语义（移动优先）：基础类服务最小屏，加前缀的类在"到达断点之后"才叠加生效。所以 `grid-cols-1 md:grid-cols-3` 的意思是"默认 1 列，`md`（≥768px）之后变 3 列"——从小到大增强。

- 一句话：**没前缀 = 移动端默认，有前缀 = 断点后增强**

**Q40: Tailwind 里自定义主题/颜色怎么做？**

**答：** 通过 `tailwind.config.js` 的 `theme.extend` 扩展设计令牌，例如 `colors: { brand: '#3b82f6' }`，之后就能写 `bg-brand`、`text-brand`。这样把"设计系统"收敛到一份配置里，保证全项目颜色、间距、字号统一。也支持 `@theme`（Tailwind v4 的 CSS-first 配置）直接在 CSS 里声明令牌。

- 一句话：**主题收敛到配置文件，类名才能保持一致**

**Q41: Tailwind 里怎么写"条件样式"（hover、focus、根据状态切换）？**

**答：** 用变体（variants）前缀：`hover:bg-blue-500`、`focus:ring-2`、`dark:bg-gray-900`、`disabled:opacity-50`。它们对应 CSS 的 `:hover`、`:focus`、`.dark`、`:disabled` 等状态，编译后自动生成对应的选择器。条件样式直接写在 class 里，不用额外写 CSS 文件。

- 一句话：**`状态前缀:工具类`，一个 class 表达一个状态下的样式**

**Q42: Tailwind 的缺点/什么时候不适合用？**

**答：** (1) HTML 的 `class` 会很长、可读性下降；(2) 团队需要学习成本，尤其要熟悉那套类名；(3) 大量重复的样式串若不抽组件，维护会变糟；(4) 动态拼接类名（如 `bg-${color}`）不会被打包器识别，会失效——这是最常见的坑。适合"组件化开发、有设计系统"的团队；不适合"要精确控制复杂 CSS、或大量动态样式"的场景。

- 加分点：说出"动态拼接类名不会生效"这个坑，说明你真用过

### 6. 性能与工程（8 题）

**Q43: 什么是重排（reflow）和重绘（repaint）？哪些属性触发重排？**

**答：** 重排 = 布局几何变化，浏览器重新计算元素的位置和尺寸，代价高；重绘 = 只重新上色，不重新布局，代价低。触发重排的属性：`width/height`、`margin/padding`、`top/left`、`display`、`font-size`、`border` 等。例外是 **`transform` 和 `opacity`**——它们走合成器，既不重排也不重绘，所以动画优先用它们。

- 一句话：**动画用 `transform`/`opacity`，别用 `top`/`left`/`width`**

**Q44: 什么是"强制同步布局"（layout thrashing）？怎么避免？**

**答：** 当代码**交错**执行"读布局尺寸"（如 `offsetWidth`、`getBoundingClientRect`）和"写布局样式"时，每次读都会强制浏览器先同步完成一次布局，反复交错就反复重排，导致卡顿。避免方式：把"读"和"写"**分批**——先把所有要读的量读出来，再统一写样式。

```js
// ❌ 反例：读一次写一次，反复强制重排
for (const el of items) {
  const w = el.offsetWidth;   // 读
  el.style.width = w + 10;    // 写
}
// ✅ 正例：先全部读，再全部写
const widths = items.map(el => el.offsetWidth);
items.forEach((el, i) => el.style.width = widths[i] + 10);
```

- 一句话：**读归读、写归写，别穿插**

**Q45: CSS 选择器的性能有什么讲究？**

**答：** 浏览器从**右往左**解析选择器，所以最右边（关键选择器）越精确越好；避免过长的后代链（`body .a .b .c`）和通配符滥用。但现实是：**选择器匹配在现代浏览器里已经非常快，除非超大页面，否则它的性能影响远小于重排/重绘**。所以优化优先级：布局抖动 > 重排频率 > 选择器。不要在写代码时为了"选择器性能"牺牲可读性。

- 一句话：**先优化重排，选择器性能是最后才考虑的事**

**Q46: CSS 动画用 `transition` 还是 `animation`？什么属性不能动画？**

**答：** `transition` 适合"两个状态之间过渡"（hover 变色、展开）；`animation` 适合"关键帧、循环、多阶段"的动画。能平滑插值的属性才适合动画：数值型（`transform`、`opacity`、`color`、`width`），而 `display`、`visibility` 这类离散属性不能平滑过渡（`display: none` 到 `block` 无法动画，可用 `opacity` + `visibility` 配合过渡替代）。

- 一句话：**能插值的才动，`display` 动不了**

**Q47: 如何组织 CSS 工程？有哪些方法论？**

**答：** 常见有 BEM（`block__element--modifier`）、CSS Modules（局部作用域）、CSS-in-JS（样式写进 JS）、原子化（Tailwind）、以及现代原生的 `@layer` 分层。选择取决于团队规模和框架：组件化开发里 CSS Modules 和 Tailwind 最流行。核心目标都一样——**避免全局污染 + 保持可维护**。

```css
/* BEM 示例 */
.card__title { }
.card__title--highlight { }

/* @layer 分层示例 */
@layer reset, base, components, utilities;
```

- 加分点：知道 `@layer` 能解决"第三方样式和我样式冲突"的优先级问题

**Q48: 什么是 `@layer`？它解决什么问题？**

**答：** `@layer` 是 CSS 原生的"层叠层"，用来**显式声明样式的优先级层级**。后声明的层优先级更高，层内的规则统一压过层外的规则（除非层外有更高的特异性/`!important`）。它解决的是"第三方库样式和业务样式谁盖谁"这个老大难——你可以把 reset、第三方、组件、工具类分别放进不同 `@layer`，精确控制覆盖顺序，而不用靠"加更长的选择器"去硬刚。

- 一句话：**`@layer` 让"谁盖谁"从"拼特异性"变成"声明顺序"**

**Q49: 为什么推荐用 `rem` 而不是 `px`？两者怎么换算？**

**答：** `rem` 是相对**根元素字号**的单位，默认 1rem = 16px。推荐 `rem` 的原因：用户可以在浏览器里改默认字号（无障碍），`rem` 会整体跟随缩放，`px` 不会；`rem` 也方便做"整站字号缩放"。换算：设计稿的 px ÷ 16 = rem，或项目里设 `html { font-size: 62.5% }` 让 1rem = 10px 方便心算（但会牺牲"跟随用户字号"的能力，需权衡）。

- 一句话：**`rem` 跟着根字号走，能响应无障碍设置**

**Q50: 一份 CSS 要能上线，工程上通常还做什么？**

**答：** (1) **预处理器/后处理器**：Sass、PostCSS（Autoprefixer 自动加厂商前缀）；(2) **压缩**：`cssnano` 等，移除空白和冗余；(3) **去未用样式**：PurgeCSS（Tailwind 内置），删除没被用到的类；(4) **代码分割**：把首屏关键 CSS 内联（Critical CSS），其余按需加载；(5) **Lint**：Stylelint 统一规范。这些让 CSS 更小、更稳、更可维护。

- 一句话：**Autoprefixer + 压缩 + 去未用 + 关键 CSS，是上线的标配**

## 二、白板手写题（Q51~Q63）

面试官说"来，手写一个布局"的时候，**先讲思路再动手**——这是第一分。布局写对 80% 也比卡住强，边写边说话。

### 1. 手写布局（5 题）

**Q51: 手写一个"水平垂直居中"？至少两种写法。**

**答：**

```css
/* 写法一：Flex（最推荐） */
.parent { display: flex; justify-content: center; align-items: center; height: 100vh; }

/* 写法二：Grid（最简洁） */
.parent { display: grid; place-items: center; height: 100vh; }

/* 写法三：绝对定位 + transform（父不是布局容器时） */
.parent { position: relative; }
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

- 讲清：`translate(-50%, -50%)` 里的 50% 是**相对子元素自身**，所以能精确居中

**Q52: 手写一个"左右两栏、左固定 200px、右自适应"的布局？**

**答：**

```css
/* Flex 写法 */
.container { display: flex; }
.sidebar { width: 200px; flex-shrink: 0; }  /* 别让它被压扁 */
.main { flex: 1; }                          /* 占剩余 */

/* Grid 写法 */
.container { display: grid; grid-template-columns: 200px 1fr; }
```

- 讲清：Flex 写法里 `flex-shrink: 0` 是防止侧栏被挤压的细节，能说出是加分项

**Q53: 手写一个"圣杯布局"（header / 三列 / footer），用 `grid-template-areas`？**

**答：**

```css
.layout {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
  grid-template-areas:
    "header header header"
    "nav    main   aside"
    "footer footer footer";
}
.header { grid-area: header; }
.nav    { grid-area: nav; }
.main   { grid-area: main; }
.aside  { grid-area: aside; }
.footer { grid-area: footer; }
```

- 讲清：每个区域名在 HTML 里用 `grid-area` 对应；改布局只改"地图"

**Q54: 手写一个"响应式卡片网格"，不用媒体查询？**

**答：**

```css
.grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
  gap: 16px;
}
```

- 讲清：`auto-fill` 自动算列数，`minmax(200px, 1fr)` 保证每列 ≥200px 且伸缩
- 追问预案："为什么不用媒体查询？"→ 因为列数应随容器宽度**连续自适应**，断点是离散的，写死 3 个断点不如这一个配方

**Q55: 手写一个"sticky 导航栏"，logo 左、菜单右？**

**答：**

```css
.nav {
  position: sticky;
  top: 0;
  display: flex;
  align-items: center;
  padding: 0 16px;
  height: 56px;
}
.nav .menu { margin-left: auto; }  /* 把菜单推到最右 */
```

- 讲清：`position: sticky; top: 0` 是"粘住"的两个必要条件
- 加分：提一句"父级不能有 `overflow: hidden` 截断滚动"

### 2. 读 CSS 说结果（3 题）

**Q56: 读下面代码，说渲染结果？**

```css
.box { display: flex; width: 600px; }
.a { flex: 1; }
.b { flex: 2; }
/* 结构：<div class="box"><div class="a">a</div><div class="b">b</div></div> */
```

**答：** `a` 宽 200px、`b` 宽 400px。因为 `flex: 1` 和 `flex: 2` 的 `basis` 都是 0，剩余空间 600px 按 1:2 分。

- 关键点：**`flex: N` 的 basis 是 0，所以按比例均分整个宽度**

**Q57: 读下面代码，说渲染结果？**

```css
.grid { display: grid; grid-template-columns: 1fr 1fr; }
.item { grid-column: span 2; }
/* 结构：<div class="grid"><div class="item">a</div><div>b</div><div>c</div></div> */
```

**答：** `a` 跨满一整行（两列），`b`、`c` 在第二行各占一列。`grid-column: span 2` 表示"横跨 2 列"。

- 关键点：**`span 2` 是跨 2 列；`1 / 3` 是"第 1 到第 3 条线"，也跨 2 列**

**Q58: 读下面代码，说渲染结果？**

```css
.parent { height: 100px; border: 1px solid; }
.child { margin-top: 30px; }
/* 结构：<div class="parent"><div class="child">x</div></div> */
```

**答：** 子元素 `margin-top: 30px` 会"穿透"父元素，导致**父元素连同子元素一起被往下推 30px**（而不是"子元素在父内部往下 30px"）。这就是父子间的外边距合并。给父加 `overflow: hidden` 或 `display: flow-root`（触发 BFC）即可阻止。

- 关键点：**父无隔离时，子的 margin 会"漏"到外面合并**

### 3. 机制讲清楚（2 题）

**Q59: 说清楚 `fr` 和 `%` 在 Grid 里的区别？**

**答：** 核心区别在**剩余空间**。`%` 相对容器总宽度，写 `50% 50%` 再加个 `gap` 就会溢出（100% + gap > 100%）；`fr` 是"扣掉固定尺寸和 `gap` 之后，把剩下的按比例分"，所以 `1fr 1fr` 加 `gap` 不会溢出。另外 `1fr` 的最小尺寸默认是内容 `min-content`，可能被长内容撑破，需要 `minmax(0, 1fr)` 兜底。

```css
/* 会溢出：两个 50% 加 gap 超过 100% */
.bad { display: grid; grid-template-columns: 50% 50%; gap: 10px; }
/* 不会溢出：fr 自动扣除 gap */
.good { display: grid; grid-template-columns: 1fr 1fr; gap: 10px; }
```

- 关键区分：**`%` 算总宽，`fr` 算剩余**

**Q60: 说清楚 `align-items` 和 `align-content` 在 Flex 里的区别？**

**答：** 两者都作用于交叉轴，但对象不同：`align-items` 管**每一行内部**子项的对齐；`align-content` 管**多行之间**的分布（只在 `flex-wrap: wrap` 且有额外空间时生效）。单行时 `align-content` 无效；多行时，`align-items` 决定"每行里的子项怎么摆"，`align-content` 决定"这一堆行在容器里怎么分布"。

```css
/* 多行 + 高度固定时，align-content: space-between 让行与行分散开 */
.container { display: flex; flex-wrap: wrap; height: 300px; align-content: space-between; }
```

- 关键区分：**`-items` 管行内，`-content` 管行间**

### 4. 综合（3 题）

**Q61: 手写一个"卡片组件"：图片区、标题、描述、底部按钮，按钮永远贴底？**

**答：**

```css
.card { display: flex; flex-direction: column; width: 260px; }
.card .body { flex: 1; }   /* 中间撑满，把按钮压到底部 */
.card .btn { margin-top: 12px; }
/* 结构：<div class="card"><img><h3>标题</h3><p>描述</p><button>按钮</button></div> */
```

- 讲清：**`flex-direction: column` + 中间内容 `flex: 1`** 是"把按钮压到底"的标准做法
- 加分：多个卡片并排时，外层套一个 `display: flex` 或 Grid，卡片加 `height: 100%` 让它们等高

**Q62: 手写一个"等高列"：三个内容长短不一的卡片，如何让它们一样高、按钮对齐？**

**答：**

```css
.row { display: grid; grid-template-columns: repeat(3, 1fr); gap: 16px; }
.card { display: flex; flex-direction: column; }
.card .body { flex: 1; }
```

- 讲清：Grid 让三列**天然等高**（同一行的网格项高度被拉伸到行高）；卡片内部再用 Flex + `flex: 1` 把按钮压到同一水平线
- 加分：Flex 也能做等高（`align-items: stretch` 默认就是），但"行内对齐"Grid 更自然

**Q63: 手写一个"移动优先的两栏布局"：默认单列堆叠，`md` 以上变成 200px + 自适应？**

**答：**

```css
.container { display: grid; grid-template-columns: 1fr; }   /* 默认单列 */
@media (min-width: 768px) {
  .container { grid-template-columns: 200px 1fr; }          /* 桌面两栏 */
}
```

- 讲清：**移动优先 = 默认写最小屏，`min-width` 从小到大增强**
- 加分：不用媒体查询的替代写法——`grid-template-columns: repeat(auto-fit, minmax(200px, 1fr))` 也能实现类似效果，但语义不同（那是"内容自适应"，这是"固定侧栏"）

## 三、一页速查表

### Flex 属性速查

| 属性 | 作用 | 常见值 / 记忆 |
|---|---|---|
| `display: flex` | 开启 flex 容器 | 块级；`inline-flex` 是行内级 |
| `flex-direction` | 主轴方向 | `row`（默认）/ `column` / `*-reverse` |
| `justify-content` | 主轴对齐 | `center` / `space-between` / `space-around` / `flex-start` |
| `align-items` | 交叉轴对齐（单行内） | `center` / `stretch`（默认）/ `flex-start` / `flex-end` |
| `align-content` | 多行在交叉轴的分布 | 仅 `flex-wrap: wrap` 时有效 |
| `flex-wrap` | 是否换行 | `nowrap`（默认）/ `wrap` / `wrap-reverse` |
| `gap` | 子项间距 | `gap: 10px`（含行 + 列，首尾无空隙） |
| `flex` | grow shrink basis 缩写 | `flex: 1` = `1 1 0%`；`flex: auto` = `1 1 auto` |
| `flex-grow` | 分剩余空间的比例 | 默认 0 |
| `flex-shrink` | 空间不足收缩比例 | 默认 1（这是"被压扁"的原因） |
| `flex-basis` | 分配前的基础尺寸 | 默认 `auto`（内容宽） |
| `align-self` | 单个子项覆盖交叉轴对齐 | `flex-end` / `center` 等 |
| `order` | 视觉顺序 | 默认 0，越小越靠前 |
| `margin-left: auto` | 把元素推到最右 | 吸收剩余空间的经典技巧 |

### Grid 属性速查

| 属性 | 作用 | 常见值 / 记忆 |
|---|---|---|
| `display: grid` | 开启 grid 容器 | 二维布局 |
| `grid-template-columns` | 定义列 | `1fr 2fr` / `repeat(3, 1fr)` / `minmax(200px, 1fr)` |
| `grid-template-rows` | 定义行 | 同上 |
| `grid-template-areas` | 布局地图 | `"header header" "sidebar main"` |
| `gap` / `row-gap` / `column-gap` | 间距 | `gap: 10px` |
| `grid-column` | 跨列 | `1 / 3`（线编号）/ `span 2` |
| `grid-row` | 跨行 | 同上 |
| `grid-area` | 对应 area 名 / 简写 | `grid-area: header` |
| `justify-items` | 子项在格内水平对齐 | `center` / `stretch`（默认） |
| `align-items` | 子项在格内垂直对齐 | `center` / `stretch` |
| `place-items` | 上两者缩写 | `place-items: center` |
| `justify-content` | 整组列在容器内分布 | 有剩余空间时有效 |
| `align-content` | 整组行在容器内分布 | 有剩余空间时有效 |
| `auto-fill` / `auto-fit` | 自动填列 | `repeat(auto-fill, minmax(200px, 1fr))` |
| `minmax(min, max)` | 轨道尺寸范围 | `minmax(0, 1fr)` 防长内容撑破 |

### 常用 Tailwind 类速查

| 想做的事 | Tailwind 类 |
|---|---|
| 开 flex / 换主轴 | `flex` / `flex-col` / `flex-row` |
| 主轴居中 / 两端对齐 | `justify-center` / `justify-between` |
| 交叉轴居中 | `items-center` / `items-stretch` |
| 等宽伸缩 / 按内容 / 不伸缩 | `flex-1` / `flex-auto` / `flex-none` |
| 换行 / 间距 | `flex-wrap` / `gap-4`（`gap-x-4` / `gap-y-4`） |
| 开 grid / 定列数 | `grid` / `grid-cols-3` |
| 跨列 | `col-span-2` |
| 内边距 / 外边距 | `p-4` / `px-4` / `m-4` / `mx-auto`（水平居中） |
| 文字大小 / 颜色 | `text-lg` / `text-red-500` / `font-bold` |
| 背景 / 边框 | `bg-white` / `border` / `rounded-lg` |
| 响应式前缀 | `md:flex` / `lg:grid-cols-3` |
| 状态变体 | `hover:bg-blue-500` / `focus:ring-2` / `dark:bg-gray-900` |
| 宽度 / 最大宽度 | `w-full` / `max-w-md` |
| 阴影 / 圆角 | `shadow` / `rounded-full` |
| 元素隐藏 / 显示 | `hidden` / `md:block` |

### 居中 N 种写法速查

| 场景 | 写法 |
|---|---|
| 水平垂直居中（最推荐） | 父 `display: flex; justify-content: center; align-items: center;` |
| 水平垂直居中（最简洁） | 父 `display: grid; place-items: center;` |
| 水平垂直居中（父非布局容器） | 子 `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%);` |
| 单行文本垂直居中 | 父 `line-height` 等于容器高度 |
| 块级元素水平居中 | 自身有 `width` + `margin: 0 auto` |
| 行内元素水平居中 | 父 `text-align: center` |
| 表格单元格居中 | `display: table-cell; vertical-align: middle;`（老旧写法，不推荐） |
| 多行内容垂直居中 | 一律用 Flex/Grid，别再用 `line-height` 凑 |

### 排查速查（样式"没生效"时按顺序查）

| 现象 | 先查这个 |
|---|---|
| `justify-content` 不生效 | 容器是不是没写 `display: flex/grid` |
| `z-index` 不生效 | 元素是不是 `position: static`；父级是不是有 `transform`/`opacity` |
| `sticky` 不粘 | 是不是没写 `top`；祖先是不是有 `overflow: hidden` |
| `width` 被压扁 | `flex-shrink` 默认 1，加 `flex-shrink: 0` |
| `1fr` 等分被撑破 | 长内容 `min-content` 太大，改 `minmax(0, 1fr)` |
| margin 间距"不够" | 外边距合并了，改用 `gap` |
| 图片撑破布局 | 加 `max-width: 100%` |
| 样式被覆盖 | 查特异性（id > class > 元素），或层叠层 `@layer` 顺序 |

## 四、面试技巧

### 4.1 不会的时候怎么救场

**核心原则：把"不知道"换成一个有价值的过程。**

- ❌ 别硬编答案。说出一句错的原理，比说"我不确定"伤害大得多。
- ✅ 可以说：**"这个属性我记不太准，但我知道它要解决的是 X 问题。能让我说下我的思路吗？"**
- ✅ 把问题**降维到你会的那一层**：不会答 `subgrid`，就说"我理解它属于 Grid 的对齐能力，要解决嵌套网格无法对齐的问题；我实际用过的是 `grid-template-areas` 把结构对齐，思路类似"。**用你掌握的等价方案接住问题。**
- ✅ 明说**边界**："这块我目前只到会用，没深入看过实现。"诚实 + 说明掌握程度，好过硬撑。
- ✅ **把追问变成加分**：被问住时反问"您是想确认渲染原理，还是想看我能不能用对？"——既争取时间，也暴露你在意需求。
- ✅ 装作思考可以，但**别装会**。面试官通常只要一句话就能分辨。

**三句万能救场句：**

1. "我先说结论，再说为什么，可以吗？"
2. "我没遇到过这个具体场景，我的推理是这样的……"
3. "这个点我回去会补，能说说你们实际是怎么处理的吗？"

### 4.2 可以反问什么

面试的最后环节，**反问的质量常常决定印象分**。按目标挑 2~3 个：

**想了解团队与工程成熟度：**

- 团队现在前端规模多大？CSS 方案是原子化（Tailwind）还是组件化（CSS Modules）？
- 你们有没有统一的设计系统/组件库？设计令牌是怎么维护的？
- 有没有专门的 UI/设计规范，还是开发自己定样式？
- 代码库的 CSS 有没有 lint（Stylelint）和构建优化（压缩、去未用）？

**想了解技术挑战与成长：**

- 目前你们前端最头疼的布局/样式问题是什么？
- 有没有历史遗留的 `float` 布局或混乱的全局 CSS，最近是否在重构？
- 新人入职前三个月，通常会遇到什么挑战？

**想了解协作方式：**

- 需求从设计稿到上线，一般怎么走？有没有设计稿标注规范？
- 代码评审的标准是什么？CSS 这块有没有统一的评审要点？
- 响应式是"桌面优先"还是"移动优先"？断点怎么定的？

**反向加分项（显示你懂工程）：**

- "你们怎么衡量页面性能？布局/样式相关的性能指标（如 CLS）有监控吗？"
- "设计稿到代码的还原，是靠手写还是靠工具（如 Tailwind + 组件库）？"

**别问的：** 薪资细节（留给 HR 环节）、能在官网查到的公开信息、以及"你们用 Flex 还是 Grid"这种能自己判断的。

### 4.3 现场写布局的 5 个习惯

1. **先复述需求 + 确认边界。** "我理解是要一个左侧固定、右侧自适应的两栏，对吗？要响应式吗？小屏怎么处理？"——这一步就能拉开差距。
2. **先讲思路再敲代码。** "我打算外层用 Grid 定两栏骨架，里面用 Flex 排卡片……"讲完再动手，避免写完发现方向错了。
3. **声明式命名要清楚。** `justify-content: space-between`、`grid-template-areas` 的命名要一眼能懂——面试官看的就是这些细节。
4. **主动指出取舍。** "这里我用 `auto-fill` 做自适应卡片，因为它比写媒体查询更省；如果卡片需要精确断点我会换成 `md:grid-cols-3`。"主动说，比被问出来强十倍。
5. **写完主动自检。** "这里有个边界：长 URL 会把 `1fr` 撑破，所以我加了 `minmax(0, 1fr)`。"——展示你有"浏览器里真实渲染"的意识。

### 4.4 高频陷阱题识别

| 听到这个问法 | 真正考的是什么 |
|---|---|
| "`flex: 1` 和 `flex: auto` 区别？" | 你知不知道 `flex-basis: 0 vs auto` 这个本质 |
| "`1fr 1fr 1fr` 为什么不总是等宽？" | 你知不知道 `fr` 的最小尺寸是内容 `min-content` |
| "`z-index: 9999` 为什么盖不住？" | 你知不知道**层叠上下文**，而不只是"要加定位" |
| "`sticky` 为什么不粘？" | 你知不知道 `top` 阈值 + 父容器 `overflow` 的限制 |
| "外边距合并是怎么回事？" | 你知不知道它**只垂直、取大值**，以及 `gap` 能绕开 |
| "居中怎么写？" | 你会不会分场景，知道哪个是"原生能力"哪个是"借来的" |
| "怎么实现响应式？" | 你会不会**移动优先 + `min-width`**，而不是张口一堆 `max-width` |
| "动画为什么卡？" | 你知不知道 `transform`/`opacity` 不触发 reflow |
| "这段 CSS 有什么问题？"（给你一段 `justify-content` 没配 `display: flex`） | 你有没有"浏览器里真实渲染"的直觉 |

**最后一条提醒：** 面试官真正想知道的只有两件事——**你能不能把布局声明成"关系"而不是"摆像素"**，以及**出问题时你能不能自己找到原因**。所有题目都是这两件事的变体。

### 4.5 CSS 面试的独有注意点

CSS 面试和 JS 面试有个本质区别：**JS 答错会报错，CSS 答错不会报错，只会"安静地渲染错"**。所以 CSS 面试官更在意你能不能**在脑子里跑一遍**，而不是背 API。

- **多画、多描述，少背属性名。** 被问"`justify-content` 和 `align-items` 区别"时，与其背定义，不如说"默认主轴水平时，一个管左右、一个管上下"——用一个具体方向代替抽象名词，面试官立刻知道你真懂。
- **主动暴露"你知道默认值"。** 比如被问 `flex-grow`，能补一句"它分的是剩余空间，默认 `basis` 是内容宽"——这句话能甩开大多数只会背 `1` 的候选人。
- **遇到不会的属性，往"布局模型"上靠。** 不会 `subgrid`，就说"我理解它属于 Grid 对齐能力，要解决嵌套网格共享轨道线的问题"——把问题降维到你会的那一层。
- **CSS 的"运行时"是浏览器。** 拿不准的时候，可以说"这个我需要在浏览器里确认一下具体表现，但我的理解是……"——诚实且专业，比硬猜强。

> 一句话记住它：**面试考的不是"你知道多少"，而是"你能不能把为什么讲清楚"。**
