# 第 10 章 · 测试题与答案

> 这一章没有新知识，只有**测量**。
> 判断你前 9 章是"读懂了"还是"看懂了"的唯一办法，是合上教程自己答一遍。
>
> 本章你需要记住的就一件事：**答不出来的地方，才是你真正需要回去补的地方。**

> 和 React 那本的"说出输出"不同，这本的难点在于 **CSS 不报错**——你写的每段 CSS 都会"安静地"渲染出某个结果，只是那个结果可能和你以为的不一样。所以这里的题目，考的全是"你脑子里的布局，和浏览器实际渲染的布局，是不是同一个"。

## 第一关 · 概念快问快答（20 题）

判断下面每句话是**对**还是**错**。不要猜，想清楚理由。

> 提示：这 20 题里对错大致各占一半，别用"感觉前面错得多、后面就对"去蒙。每句话要么是"规范明确规定的行为"（对），要么是"把某个属性名、默认值、方向搞反了"（错）。

1. `flex: 1` 是 `flex-grow: 1; flex-shrink: 1; flex-basis: 0%` 的缩写。
2. `flex: auto` 等价于 `flex: 1 1 auto`，它的 `flex-basis` 是内容自身的宽度。
3. Flex 容器默认的 `flex-direction` 是 `column`。
4. Flex 里 `justify-content` 控制的是交叉轴对齐，`align-items` 控制的是主轴对齐。
5. 给所有 flex 子项都设 `flex-grow: 1`，它们就一定会等宽。
6. `flex-shrink` 的默认值是 `0`，所以 flex 子项默认不会被压缩。
7. Grid 里写 `grid-template-columns: 1fr 1fr 1fr`，三列一定严格等宽。
8. Grid 里 `repeat(3, 1fr)` 和 `repeat(3, auto)` 的效果完全一样。
9. `grid-template-areas` 用多个字符串表示多行，同一个字符串里用空格分隔不同列。
10. BFC（块级格式化上下文）可以阻止子元素的 `margin-top` 与自身合并（"穿透"）。
11. 两个上下相邻的块级元素，一个 `margin-bottom: 20px`，一个 `margin-top: 30px`，它们之间的实际间距是 30px。
12. 水平方向相邻元素的 `margin` 也会像垂直方向那样发生合并。
13. 两个都设了 `position: relative` 的兄弟元素，`z-index` 大的那个会盖在上面。
14. `position: sticky` 的行为介于 `relative` 和 `fixed` 之间。
15. `position: sticky` 的元素一旦滚动过阈值，就会一直固定在视口里，不再受父容器边界限制。
16. "移动优先"的响应式写法是：基础样式按移动端写，再用 `min-width` 的媒体查询逐步增强桌面端。
17. `@media (min-width: 768px)` 表示"屏幕宽度小于等于 768px 时生效"。
18. Tailwind 的原子类一个 class 只干一件事，例如 `p-4` 只负责设置 padding。
19. Tailwind 里的 `flex-1` 等价于 CSS 的 `flex: 1 1 0%`。
20. `box-sizing: border-box` 让 `width` 把 `padding` 和 `border` 也算进去。

## 第一关答案

| # | 答案 | 解析 | 出处 |
|---|---|---|---|
| 1 | **对** | `flex` 是 `flex-grow flex-shrink flex-basis` 三个值的缩写；只写一个数字时，`flex-basis` 默认变成 `0%`。 | 02 章 |
| 2 | **对** | `flex: auto` 展开就是 `1 1 auto`，基准是内容自身宽度——所以它先保证内容宽度，再分剩余空间。 | 02 章 |
| 3 | **错** | 默认是 `row`（水平方向），`column` 需要显式声明。 | 02 章 |
| 4 | **错** | 说反了：`justify-content` 控制**主轴**，`align-items` 控制**交叉轴**。默认主轴是水平方向，所以 `justify-content` 管左右、`align-items` 管上下。 | 02 章 |
| 5 | **错** | `flex-grow: 1` 只负责"按比例分剩余空间"，最终宽度还要看 `flex-basis`（默认 `auto`，即内容宽度）。内容长的那个基础更宽，分完还是更宽。想严格等宽要 `flex: 1`（basis 为 0）。 | 02 章 |
| 6 | **错** | 默认值是 `1`，子项**默认就会收缩**。这也是"设了 `width` 却被压扁"的常见原因。 | 03 章 |
| 7 | **错** | `fr` 的最小尺寸默认是 `auto`（内容的最小宽度）。某一列放一个超长单词/长 URL，它会把那一列撑宽，三列就不再等分。严格等分要 `minmax(0, 1fr)` 或给子项 `min-width: 0`。 | 04 章 |
| 8 | **错** | `1fr` 是"按比例分剩余空间"，`auto` 是"按内容大小决定"。前者会把空间撑满，后者有多宽占多宽。 | 04 章 |
| 9 | **对** | 一个字符串 = 一行，字符串内空格分隔 = 不同列，多个字符串 = 多行。每行字符串的列数必须一致，否则整条规则失效。 | 05 章 |
| 10 | **对** | 触发 BFC（如 `overflow: hidden`、`display: flow-root`）后，子元素的 `margin-top` 不会穿透到外面跟父元素合并。这也是 BFC 的经典用途之一。 | 01 章 |
| 11 | **对** | 垂直方向的相邻 `margin` 会**合并取较大值**：`max(20, 30) = 30`，不是 `50`。这是规范明确设计的"外边距合并"。 | 01 章 |
| 12 | **错** | 外边距合并**只发生在垂直方向**，水平方向（左右相邻）不合并。 | 01 章 |
| 13 | **对** | 前提是两者在**同一个层叠上下文**里、且都非 `static`。`z-index` 越大越靠上；都没设 `z-index` 时，后写的盖先写的。 | 01 章 |
| 14 | **对** | 滚动到阈值前表现像 `relative`（还在文档流里），超过阈值后像 `fixed`（固定在视口内某位置）。 | 01 章 |
| 15 | **错** | sticky 的"粘住"受**父容器边界**限制：父容器滚出视口，sticky 元素会被一起带走，不会无限地粘在视口里。 | 01 章 |
| 16 | **对** | 移动优先 = 默认样式服务最小屏幕，用 `min-width` 断点从小到大增强。反过来的 `max-width` 是"桌面优先"。 | 07 章 |
| 17 | **错** | `min-width: 768px` 是"最小宽度 768px"，即**大于等于** 768px 时生效。 | 07 章 |
| 18 | **对** | 原子类的核心就是"单一职责"：一个类只对应一条（或极少几条）CSS 声明，靠组合来表达复杂样式。 | 08 章 |
| 19 | **对** | Tailwind 的 `flex-1` 展开就是 `flex: 1 1 0%`。注意它和 `flex-auto`（`flex: 1 1 auto`）不一样。 | 08 章 |
| 20 | **对** | `border-box` 下，`width` = 内容 + `padding` + `border` 的总和，写多少就是多少，不会出现"内容把盒子撑破"的经典坑。 | 01 章 |

**这一关你真正在防的，是"直觉陷阱"。** 上面 20 题里，错题基本都栽在同一个地方：**用命令式的直觉去猜 CSS 声明式的结果**。你直觉上以为"`flex-grow: 1` 就是等宽"，但 CSS 的规则是"按比例分剩余空间"；你直觉上以为"设了 20 和 30 就该是 50"，但规范写的是"垂直合并取大值"。**别和规则较劲，把规则记下来。** 凡是你答错的题，都在提醒你：这里有一个"你以为的"和"浏览器实际的"不一致，那正是你需要重建的心智模型。

> 一句话记住它：**CSS 没有玄学，只有你还没背下来的规则。**

## 第二关 · 说出渲染结果（25 题）

下面每段 CSS（配合注释里说明的 HTML 结构），**渲染出来的布局/效果是什么**？

> 作答约定：注释里写 `结构：...` 的是 HTML 骨架（`>` 表示父子关系，如 `<div class="box"><div>a</div></div>` 就是 box 里放一个 a）；没特别说明尺寸的，默认子项宽度就是"内容有多宽就有多宽"。答的时候描述"谁在左、谁在右、谁变宽了、间距是多少"，不用精确到像素。

```css
/* 1 结构：<div class="box"><div>a</div><div>b</div><div>c</div></div> */
.box { display: flex; }

/* 2 结构：同上 */
.box { display: flex; flex-direction: column; }

/* 3 结构：<div class="box"><div>a</div><div>b</div><div>c</div></div>，容器宽 600px，子项各宽 100px */
.box { display: flex; justify-content: space-between; }

/* 4 结构：<div class="box"><div>a</div><div>b</div></div>，容器高 100px */
.box { display: flex; align-items: center; height: 100px; }

/* 5 结构：<div class="box"><div class="a">a</div><div class="b">b</div><div class="c">c</div></div>，容器宽 600px，子项各宽 100px */
.box { display: flex; }
.a { flex-grow: 1; }
.b { flex-grow: 2; }

/* 6 结构：<div class="box"><div>aaa</div><div>bbb</div><div>ccc</div></div>，容器宽 600px */
.box { display: flex; }
.box > div { flex: 1; }

/* 7 结构：<div class="box"><div class="a">一段很长很长不换行的连续文字</div><div class="b">短</div></div>，容器宽 600px */
.box { display: flex; }
.a, .b { flex: 1; }

/* 8 结构：<div class="grid"><div>1</div>...<div>6</div></div>，共 6 个子项 */
.grid { display: grid; grid-template-columns: 1fr 2fr 1fr; }

/* 9 结构：同上，6 个子项 */
.grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 10px; }

/* 10 结构：<div class="grid"><header>头</header><aside>侧</aside><main>主</main><footer>尾</footer></div> */
.grid {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}

/* 11 结构：<div class="grid"><div class="a">a</div><div>b</div><div>c</div></div> */
.grid { display: grid; grid-template-columns: repeat(3, 1fr); }
.a { grid-column: 1 / 3; }

/* 12 结构：<div class="grid"><div>a</div><div>b</div></div>，容器宽 500px */
.grid { display: grid; grid-template-columns: minmax(200px, 1fr) 1fr; }

/* 13 结构：<div class="box"><div class="item">中</div></div>，容器高 200px */
.box { display: flex; justify-content: center; align-items: center; height: 200px; }

/* 14 结构：同上 */
.box { display: grid; place-items: center; height: 200px; }

/* 15 结构：<div class="item">块</div>，item 有固定宽高 */
.item { width: 100px; height: 50px; margin: 0 auto; }

/* 16 结构：<div class="box"><div>a</div><div>b</div></div> */
.box { display: flex; }
.box > div:last-child { margin-left: auto; }

/* 17 结构：<div class="box"><div>a</div><div>b</div><div>c</div></div>，容器高 100px */
.box { display: flex; align-items: flex-start; height: 100px; }
.box > div:nth-child(2) { align-self: flex-end; }

/* 18 结构：<div class="box"><div>a</div><div>b</div><div>c</div></div>，容器宽 300px */
.box { display: flex; flex-wrap: wrap; }
.box > div { width: 50%; }

/* 19 结构：<div class="box"><div>a</div><div>b</div><div>c</div></div> */
.box { display: flex; gap: 10px; }

/* 20 结构：<div class="box"><div class="a">a</div><div class="b">b</div><div class="c">c</div></div> */
.box { display: flex; }
.c { order: -1; }

/* 21 结构：<div class="grid"><div>1</div>...<div>8</div></div>，容器宽 400px */
.grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(100px, 1fr)); }

/* 22 结构：<header class="nav">导航</header> 之后是一长段可滚动的内容 */
.nav { position: sticky; top: 0; }

/* 23 结构：<div class="parent"><div class="child"></div></div>，parent 尺寸 200x100 */
.parent { position: relative; width: 200px; height: 100px; }
.child { position: absolute; top: 10px; right: 10px; }

/* 24 结构：<div class="a">A</div><div class="b">B</div> */
.a { margin-bottom: 20px; }
.b { margin-top: 30px; }

/* 25 结构：<div class="box">内容</div> */
.box { box-sizing: border-box; width: 100px; padding: 10px; border: 5px solid #000; }
```

## 第二关答案

下表里的「渲染结果」都可在浏览器里真实复现。**合上答案先在脑子里渲染一遍，再看。**

| # | 渲染结果 | 关键点 |
|---|---|---|
| 1 | 三个子项水平排成一行，从左到右 a、b、c，宽度各自只够放下内容。 | `display: flex` 让子项沿主轴（默认水平）排列。 |
| 2 | 三个子项垂直排成一列，从上到下 a、b、c。 | `flex-direction: column` 把主轴从水平改成垂直。 |
| 3 | a 贴最左、c 贴最右，b 在正中间；三者的间距是"剩余空间均分"（300px 分成两段，每段 150px）。 | `space-between` 把剩余空间平均分配到子项之间，首尾不留空。 |
| 4 | a、b 在垂直方向居中（交叉轴居中），水平方向仍靠左。 | `align-items` 管交叉轴；默认主轴水平，所以它管的是"上下居中"。 |
| 5 | 剩余空间 300px 按 1:2 分：a 变 200px，b 变 300px，c 保持 100px。 | `flex-grow` 按**比例**分剩余空间；没设的项保持原宽度。 |
| 6 | 三个子项等宽，各占 200px。 | `flex: 1` 的 `flex-basis` 是 0，把内容宽度先"清零"，再均分，所以严格等宽。 |
| 7 | 理论上各占一半，但 `.a` 里的长文字不换行，它的 `min-content` 宽度很大，会把 `.a` 撑宽，导致两列不再等分（甚至溢出容器）。 | `flex: 1` 的 `basis: 0` 不等于"能缩到 0"；要严格等分需给子项 `min-width: 0`。 |
| 8 | 三列，中间列宽是两侧的两倍；6 个格子按"从左到右、换行"自动排满。 | `1fr 2fr 1fr`：`fr` 按比例分剩余空间。 |
| 9 | 3 列等宽，行与行、列与列之间都有 10px 间距。 | `repeat(3, 1fr)` + `gap: 10px`；`gap` 同时管行列。 |
| 10 | 头、尾各占满两列；侧栏在左（固定 200px）、主内容在右（占剩余）。 | `grid-template-areas` 用字符串拼出布局地图；同一行的单元格用空格连，跨列靠"名字写两遍"。 |
| 11 | a 横跨第 1、2 列；b 落到第 3 列；c 换到下一行的第 1 列。 | `grid-column: 1 / 3` 的 3 是"到第 3 条网格线为止"，占 1、2 两格。 |
| 12 | 第一列最小 200px，剩余 300px 两列按 1:1 分，最终各约 250px。 | `minmax(200px, 1fr)` 先保底 200px，再把剩余按 `1fr` 分配。 |
| 13 | item 在水平、垂直两个方向都居中。 | `justify-content` + `align-items` 双 `center` 是 flex 居中三件套之二。 |
| 14 | item 水平垂直居中，效果同上题，但只写一行。 | `place-items: center` 是 `align-items` + `justify-items` 的缩写。 |
| 15 | item 水平居中，垂直方向仍靠顶。 | `margin: 0 auto` 只把**水平**剩余空间平均分到左右；垂直不生效。 |
| 16 | a 靠左，b 被推到最右边（整体像 `space-between`）。 | `margin-left: auto` 会吸收所有剩余空间——这是 flex 里"把一个元素顶到另一头"的经典写法。 |
| 17 | a、c 贴顶部，b 单独贴底部。 | `align-self` 只覆盖**自己**的交叉轴对齐，不影响别人。 |
| 18 | 一行放不下三个（每个 50% 即 150px，容器 300px 只能放 2 个），所以 a、b 在一行，c 换到第二行。 | `flex-wrap: wrap` 允许换行；每个子项宽 50%，每行最多 2 个。 |
| 19 | 三个子项之间各有 10px 间距，首尾没有多余空隙。 | `gap` 只产生在相邻子项之间，不含首尾。 |
| 20 | 显示顺序变成 c、a、b。 | `order` 改变视觉顺序；默认都是 0，`-1` 会排到最前。 |
| 21 | 每列最小 100px，容器 400px 时放 4 列（各约 100px）；容器变宽会自动增加列数，变窄会减列并自动换行。 | `auto-fill` 按可用空间尽可能多塞列，配合 `minmax` 实现"响应式卡片墙"。 |
| 22 | 页面滚动时，导航先随文档流走；当它到达距视口顶部 0px 的位置后就"粘"在顶部不动，直到父容器滚出视口。 | `sticky` 必须配 `top`（或 `bottom`）才有阈值；它受父容器边界限制。 |
| 23 | child 定位在 parent 的右上角，距离上边 10px、距离右边 10px。 | `absolute` 相对最近的 `position: relative` 祖先定位，不是相对视口。 |
| 24 | A、B 之间的间距是 30px，不是 50px。 | 垂直相邻 `margin` 合并取较大值 `max(20, 30)`。 |
| 25 | 盒子总宽 100px，其中内容区宽 70px（100 - 2×10 - 2×5）。 | `border-box` 让 `width` 包含 `padding` 和 `border`。 |

**这一关你真正在练的三件事：**

1. **在心里建立一台"浏览器"**：看到 `display: flex`，立刻知道子项会沿主轴排；看到 `1fr 2fr`，立刻知道是"分剩余空间的比例"。这个"脑子里渲染"的能力，是区分"会用"和"真懂"的分水岭。
2. **看清"基础值"再算结果**：`flex-grow` 分的是**剩余空间**，不是容器宽度；`fr` 的最小尺寸是内容的 `min-content`，不是 0。所有"算错"，几乎都是漏了某个默认值。
3. **分清"声明的是关系还是个体"**：`justify-content` 声明的是"这一排元素的关系"，`margin-left: auto` 声明的是"这一个人的位置"。混用了，渲染结果就和你想的不一样。

> 一句话记住它：**渲染结果不靠猜，靠"默念一遍默认值 + 分清关系/个体"算出来。**

## 第三关 · 改错（10 题）

每题给你一段**能复现出问题**的 HTML+CSS。先别看修正代码，自己找。

**这一关怎么练：** 拿到问题代码，先在脑子里（或浏览器里）跑一遍，问自己三个问题——**"哪个属性没生效？它缺了什么前置条件？怎么补？"**。CSS 的 bug 几乎从不说"报错"，它只是"安静地不按你想的来"，所以这一关考的就是你能不能**从现象反推出缺了哪个前置条件**。如果你一眼看不出毛病，回到第二关，把"脑子里渲染"的能力先补起来。

### 3.1 没开 Flex 就想用 `justify-content`

**问题代码：**

```html
<div class="box">
  <div>a</div>
  <div>b</div>
</div>
```

```css
.box {
  justify-content: center;   /* ❌ 容器根本不是 flex/grid */
}
```

**症状：** 两个子项照样从左上角堆下来（各占一行），`justify-content` 完全没生效，也没有任何报错提示。

**为什么：** `justify-content` 是 Flex/Grid **容器**才有的属性，对一个普通块级元素（`display: block`）它没有任何意义，浏览器直接忽略。

**修正代码：**

```css
.box {
  display: flex;             /* ✅ 先声明成 flex 容器 */
  justify-content: center;
}
```

### 3.2 flex 子项设了 `width` 却被压扁

**问题代码：**

```html
<div class="box">
  <div class="item">这是一段会被压扁的内容</div>
  <div class="item">另一段</div>
</div>
```

```css
.box { display: flex; }
.item {
  width: 200px;              /* ❌ 以为固定 200px */
}
```

**症状：** 容器宽度不足时，`.item` 被压得比 200px 窄，内容溢出或换行。

**为什么：** `flex-shrink` 默认是 `1`，意味着"空间不够时允许收缩"。你只写了 `width`，没关掉收缩，浏览器照样会把它压扁。

**修正代码：**

```css
.item {
  width: 200px;
  flex-shrink: 0;            /* ✅ 不允许收缩 */
}
```

### 3.3 `grid-template-areas` 各行列数不一致

**问题代码：**

```html
<div class="grid">
  <header>头</header>
  <aside>侧</aside>
  <main>主</main>
  <footer>尾</footer>
</div>
```

```css
.grid {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer footer";  /* ❌ 这行 3 列，和上面 2 列不一致 */
}
```

**症状：** 整个 `grid-template-areas` 规则被浏览器**整体丢弃**，布局退化成默认的单列堆叠。

**为什么：** `grid-template-areas` 要求每一行的字符串**列数必须一致**，否则规则无效。这里前两行 2 列、第三行 3 列，浏览器直接放弃这条声明。

**修正代码：**

```css
grid-template-areas:
  "header header"
  "sidebar main"
  "footer footer";           /* ✅ 每行都是 2 列 */
```

### 3.4 `1fr` 等分被超长内容撑破

**问题代码：**

```html
<div class="grid">
  <div class="col">https://example.com/this-is-a-very-very-long-url-that-wont-break</div>
  <div class="col">短</div>
</div>
```

```css
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;   /* ❌ 期望两列等分 */
}
```

**症状：** 左列里的长 URL 不换行，把左列撑得比右列宽很多，甚至溢出容器。

**为什么：** `1fr` 的最小尺寸默认是 `auto`，也就是内容的最小宽度（`min-content`）。长内容的最小宽度很大，`1fr` 无法把它压缩到"等分"的大小。

**修正代码：**

```css
.grid {
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(0, 1fr);   /* ✅ 允许缩到 0 */
}
/* 或给子项加 min-width: 0 */
```

### 3.5 外边距合并导致"压不下来"

**问题代码：**

```html
<div class="a">A</div>
<div class="b">B</div>
```

```css
.a { margin-bottom: 20px; }
.b { margin-top: 30px; }   /* ❌ 以为中间是 50px */
```

**症状：** A、B 之间的实际间距是 30px，比你期望的 50px 少，怎么调都"压不下去"。

**为什么：** 垂直方向的相邻 `margin` 会**合并取较大值**。这是规范设计的行为，不是 bug。

**修正代码：**

```css
/* 方案一：只留一边的 margin */
.a { margin-bottom: 50px; }
.b { margin-top: 0; }

/* 方案二：用 flex 容器的 gap，不存在合并 */
.box { display: flex; flex-direction: column; gap: 50px; }
```

### 3.6 `z-index` 设了却没效果

**问题代码：**

```html
<div class="page">
  <div class="modal">弹窗</div>
</div>
```

```css
.modal {
  z-index: 9999;            /* ❌ 没有定位，z-index 被忽略 */
}
```

**症状：** 弹窗还是被别的元素盖住，`z-index: 9999` 形同虚设。

**为什么：** `z-index` 只对 `position` 不为 `static` 的元素（或 flex/grid 容器的直接子项）生效。一个普通 `static` 元素设 `z-index` 会被忽略。

**修正代码：**

```css
.modal {
  position: relative;       /* ✅ 先给定位 */
  z-index: 9999;
}
```

### 3.7 `sticky` 没粘住

**问题代码：**

```html
<header class="nav">导航栏</header>
<main class="content">
  <!-- 这里是一长段可滚动的内容 -->
</main>
```

```css
.nav {
  position: sticky;         /* ❌ 没写 top，等于没阈值 */
}
```

**症状：** 导航跟着页面一起滚走，完全没有"粘住"的效果。

**为什么：** `sticky` 本身不产生任何位移，必须配合 `top`/`bottom` 之类的阈值，浏览器才知道"滚到哪开始粘"。另外，如果某个祖先设置了 `overflow: hidden`，`sticky` 也会失效。

**修正代码：**

```css
.nav {
  position: sticky;
  top: 0;                   /* ✅ 粘在容器顶部 */
}
/* 并确认父级没有 overflow: hidden 截断滚动 */
```

### 3.8 移动优先写成了桌面优先

**问题代码：**

```html
<div class="container">
  <div>1</div>
  <div>2</div>
  <div>3</div>
</div>
```

```css
.container { grid-template-columns: 1fr 1fr 1fr; }   /* ❌ 默认写死三列 */
@media (max-width: 768px) {
  .container { grid-template-columns: 1fr; }          /* ❌ 用 max-width 往回收 */
}
```

**症状：** 功能上能跑通，但违背了"移动优先"，断点多了之后逻辑绕、易漏、且覆盖顺序容易写错。

**为什么：** 用 `max-width` 是"桌面优先，向下适配"，和主流的移动优先反着来。移动优先应当默认写最小屏幕，用 `min-width` 从小到大增强。

**修正代码：**

```css
.container { grid-template-columns: 1fr; }            /* ✅ 默认移动端单列 */
@media (min-width: 768px) {
  .container { grid-template-columns: 1fr 1fr 1fr; } /* ✅ 变宽才加列 */
}
```

### 3.9 块级元素 `margin: 0 auto` 没居中

```html
<div class="card">

</div>
```

```css
  margin: 0 auto;          /* ❌ 想让块级元素水平居中 */
}
```

```css
}
```

## 第四关 · 面试问答（15 题）

出声讲一遍，不要在心里默读。每题下方的引用块是**面试官真正想听到的点**。

**这一关怎么练：** 用手机录音，或对着镜子把每题讲 30 秒。讲的时候注意——**先给结论，再给因果，最后补一句"所以怎么用"**。比如被问"`flex: 1` 和 `flex: auto` 区别"，标准讲法是："区别在 `flex-basis`，`flex: 1` 是 0、`flex: auto` 是 auto，所以一个等宽、一个按内容……"——不要一上来就背 `flex-grow flex-shrink flex-basis` 那三个单词，那样反而显得在背八股。

### 第 1 题

**Q：Flexbox 和 Grid 到底怎么选？**

**A：** 一句话：**一维用 Flex，二维用 Grid**。如果布局的约束是"一行或一列里的元素怎么排列、怎么对齐、怎么伸缩"，用 Flex；如果是要同时控制"行和列"的网格骨架（比如整体页面框架），用 Grid。两者不冲突，Flex 处理"组件内部的一排按钮"，Grid 处理"页面级的行列骨架"，嵌套使用是常态。

```css
/* 页面骨架用 Grid */
.layout { display: grid; grid-template-areas: "header header" "sidebar main"; }
/* 导航栏内部的一排按钮用 Flex */
.nav { display: flex; justify-content: space-between; }
```

> **面试官想听到的要点：** 不要只说"都行"。要能给出**判定标准**——"内容驱动（Flex）vs 布局驱动（Grid）"，并举例说明它们常嵌套使用。

### 第 2 题

**Q：`flex: 1` 到底是个什么缩写？和 `flex: auto` 有什么区别？**

**A：** `flex: 1` 展开是 `flex-grow: 1; flex-shrink: 1; flex-basis: 0%`；`flex: auto` 展开是 `1 1 auto`。核心区别在 `flex-basis`：`0%` 表示"先把内容宽度清零再分剩余空间"，所以 `flex: 1` 能让多个子项**严格等宽**；`auto` 表示"先保证内容自身宽度，再分剩余空间"，所以 `flex: auto` 下的子项宽窄由内容决定。

```css
.a { flex: 1; }     /* basis: 0 → 等宽 */
.b { flex: auto; }  /* basis: auto → 按内容 */
```

> **面试官想听到的要点：** 点出 `flex-basis: 0 vs auto` 这一处关键区别，并能说出"等宽用 `flex: 1`，不等宽用 `flex: auto`"。

### 第 3 题

**Q：`flex-grow` 是怎么算的？**

**A：** 先算出**剩余空间**（容器宽度 − 所有子项的基础宽度之和），再按各子项 `flex-grow` 的**比例**把剩余空间分给它们。注意：基础宽度来自 `flex-basis`，默认是 `auto`（内容宽度）。所以"都设 `flex-grow: 1` 就等宽"是错的——内容不同，基础宽度不同，分完还是不等宽。

```css
/* 容器 600px，三个子项各 100px，剩余 300px */
.a { flex-grow: 1; }   /* 100 + 300*1/3 = 200px */
.b { flex-grow: 2; }   /* 100 + 300*2/3 = 300px */
.c { }                 /* 保持 100px */
```

> **面试官想听到的要点：** 能讲清"剩余空间"这个概念，以及 `flex-grow` 是"按比例分剩余"，不是"设个宽度"。

### 第 4 题

**Q：`1fr 1fr 1fr` 三列为什么不总是等宽？**

**A：** 因为 `fr` 单位的最小尺寸默认是 `auto`，也就是"内容的最小宽度"（`min-content`）。某一列放一个超长单词或长 URL，它的 `min-content` 很大，`1fr` 无法把它压缩到等分，于是那一列就被撑宽了。解决：用 `minmax(0, 1fr)` 把最小尺寸压成 0，或者给子项加 `min-width: 0`。

```css
.grid { grid-template-columns: 1fr 1fr 1fr; }        /* 可能不等分 */
.grid { grid-template-columns: repeat(3, minmax(0, 1fr)); }  /* 严格等分 */
```

> **面试官想听到的要点：** 知道 `fr` 的本质是"剩余空间的比例单位"，但**最小尺寸默认是 auto**；能给出 `minmax(0, 1fr)` 这个标准解法。

### 第 5 题

**Q：BFC 是什么？它解决了哪些问题？**

**A：** BFC（Block Formatting Context，块级格式化上下文）是页面上一个**独立的渲染区域**，里面的布局不会影响外面。它主要有三个用途：(1) **清除浮动**——BFC 会包含内部浮动的子元素，解决父容器高度塌陷；(2) **阻止外边距合并穿透**——父子元素间的 `margin-top` 不再合并到外面；(3) **隔离浮动**——不让浮动元素覆盖到 BFC 区域内部。触发方式：`overflow: hidden`、`display: flow-root`、`float`、绝对定位等。

> **面试官想听到的要点：** 至少说出两个用途（清浮动 + 阻止 margin 合并），并知道 `display: flow-root` 是"纯粹为了触发 BFC"的现代写法。

### 第 6 题

**Q：什么是外边距合并（margin collapsing）？怎么避免？**

**A：** 垂直方向上，两个相邻块级元素的 `margin` 会**合并成较大值**（而不是相加）；父子元素之间也会合并（父元素没有 `border`/`padding`/BFC 隔离时）。这是规范明确设计的行为，为了排版美观。避免方式：(1) 只在一侧设 `margin`；(2) 用 `padding` 替代；(3) 给父元素触发 BFC；(4) 用 Flex/Grid 容器的 `gap`（压根没有合并这回事）。

> **面试官想听到的要点：** 能说出"只发生在垂直方向、取较大值"这两个要点，并知道现代布局用 `gap` 绕开它。

### 第 7 题

**Q：`z-index` 为什么不生效？**

**A：** 最常见的原因是**元素没有定位**——`z-index` 只对 `position` 不为 `static` 的元素（或 flex/grid 容器的直接子项）生效。另一个更隐蔽的原因是**层叠上下文**：`z-index` 只在同一个层叠上下文里比较。如果父级自己创建了一个层叠上下文（比如父级有 `opacity`/`transform`/`filter`），那么子元素再大的 `z-index` 也出不了父级那一层，盖不过外面的元素。

```css
.parent { transform: translateZ(0); }  /* 父级开了层叠上下文 */
.child { z-index: 9999; }              /* 但盖不过 .parent 外面的兄弟元素 */
```

> **面试官想听到的要点：** 先说"没定位"这个高频原因，再补"层叠上下文"这个进阶原因——后者是加分项，说明你真的懂层叠。

### 第 8 题

**Q：`position` 五个值分别是什么？`sticky` 的机制讲一下。**

**A：** `static`（默认，正常文档流）、`relative`（相对自身原位置偏移，仍占位）、`absolute`（相对最近的定位祖先，脱离文档流）、`fixed`（相对视口，脱离文档流）、`sticky`（介于 `relative` 和 `fixed` 之间）。`sticky` 在滚动到阈值（`top`/`bottom` 等）之前表现像 `relative`，超过阈值后像 `fixed` 一样粘住；但它的"粘住"受**父容器边界**限制，父容器滚出视口，它也会被带走。

```css
.nav { position: sticky; top: 0; }   /* 滚到顶部就粘住，父容器滚走它也走 */
```

> **面试官想听到的要点：** 能说清 `absolute` 锚定的是"最近定位祖先"而非视口；能说清 `sticky` 的"相对 → 固定"切换 + 受父容器限制。

### 第 9 题

**Q：移动优先的响应式怎么做？`min-width` 和 `max-width` 哪个好？**

**A：** 移动优先 = 默认样式按最小屏幕写，然后用 `min-width` 断点**从小到大**增强桌面端。推荐 `min-width`，因为它和"默认最简、逐级增强"的思路一致，覆盖顺序更直观、更不容易漏。`max-width` 是"桌面优先、向下适配"，默认写复杂样式再往回收，断点多了容易乱。此外还有 `@container` 容器查询，可以按"容器宽度"而非"视口宽度"响应。

```css
.container { grid-template-columns: 1fr; }            /* 默认移动端 */
@media (min-width: 768px) {                            /* 从小到大增强 */
  .container { grid-template-columns: 1fr 1fr 1fr; }
}
```

> **面试官想听到的要点：** 说出"移动优先 + `min-width` 从小到大"这个组合，并能顺带提一句容器查询是更细粒度的方案。

### 第 10 题

**Q：`box-sizing: content-box` 和 `border-box` 有什么区别？为什么推荐 `border-box`？**

**A：** `content-box`（默认）下，`width` 只指**内容区**，`padding` 和 `border` 是额外加上的，所以实际总宽 = `width + padding + border`；`border-box` 下，`width` 直接是**总宽**，`padding` 和 `border` 都从里面扣。推荐 `border-box` 是因为它更符合直觉——你写 `width: 100px` 就是 100px，不会因为加了 `padding` 就把盒子撑破、把布局挤乱。

```css
* { box-sizing: border-box; }   /* 现代工程的标配 */
```

> **面试官想听到的要点：** 能画清"总宽 = ? "这个算式，并说出 `border-box` 是"所见即所得"。

### 第 11 题

**Q：Tailwind 的原子类和传统 CSS 类比，各有什么优劣？**

**A：** 原子类的优点是**开发快、样式本地化、无命名负担**——你不用给每个元素想类名，改一个按钮就只动那一行 HTML。缺点是 HTML 变长、类名堆叠显得"脏"，且需要团队熟悉那套类名。传统语义类（`.card`、`.btn`）的优点是**语义清晰、复用度高**，缺点是要维护一套命名体系、要处理样式的全局污染。两者不是对错问题，是"分离的粒度"不同——Tailwind 按"设计令牌"分离，传统按"组件语义"分离。

> **面试官想听到的要点：** 不要站队。能说出"它把分离的维度从'文件'换成了'设计令牌'"，并能提一句"大量重复的样式应抽成组件，而不是复制一长串类名"。

### 第 12 题

**Q：实现水平垂直居中，说出至少 3 种写法，并比较。**

**A：** (1) **Flex**：父 `display: flex; justify-content: center; align-items: center`——最通用、最推荐；(2) **Grid**：父 `display: grid; place-items: center`——一行搞定，最简洁；(3) **绝对定位 + transform**：子 `position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)`——适合"父容器不是布局容器"的场景，但要知道子元素的 50% 是相对自身；(4) **`margin: auto`**：只对"有固定宽高且父是 flex/grid"或"水平方向有宽度"的块级元素有效。日常首选 Flex/Grid，因为它们是"为布局而生"的能力，而不是"借来的"。

```css
/* 方案一：Flex */
.parent { display: flex; justify-content: center; align-items: center; height: 200px; }
/* 方案二：Grid */
.parent { display: grid; place-items: center; height: 200px; }
/* 方案三：绝对定位 */
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }
```

> **面试官想听到的要点：** 能横向比较"哪个是原生的、哪个是借来的"，而不是只背写法。

### 第 13 题

**Q：容器查询（Container Queries）解决什么问题？和媒体查询有什么区别？**

**A：** 媒体查询响应的是**视口**（屏幕宽度），容器查询响应的是**某个容器自身的宽度**。它的价值在于"组件级响应"：同一个卡片，放到宽的主栏是横排、放到窄的侧栏是竖排，不用关心整个页面多宽。这解决了媒体查询最大的局限——组件无法"自我感知"自己所在容器的空间。

```css
.card-container { container-type: inline-size; }
@container (min-width: 400px) {
  .card { flex-direction: row; }   /* 容器够宽就横排，和页面宽度无关 */
}
```

> **面试官想听到的要点：** 一句话点出"媒体查询响应视口，容器查询响应容器"这个本质区别，并举出"同一组件在不同容器里表现不同"的场景。

### 第 14 题

**Q：什么是层叠上下文（Stacking Context）？什么时候会意外地创建它？**

**A：** 层叠上下文是一个"让元素在 z 轴上独立排序"的盒子，`z-index` 只在同一个层叠上下文里比较。意外创建它的常见情况：`position` + `z-index`、`opacity < 1`、`transform`、`filter`、`will-change` 等。最常见的坑：父级有 `opacity` 或 `transform`，结果里面子元素的 `z-index: 9999` 也盖不过外层的兄弟元素——因为它被锁在了父级那一层里。

> **面试官想听到的要点：** 能举出"父级 `transform`/`opacity` 让子元素 `z-index` 失效"这个具体现象，而不是只背"层叠上下文"这个词。

### 第 15 题

**Q：哪些 CSS 属性会触发布局重排（reflow）？性能上该怎么注意？**

**A：** 触发 reflow 的是"影响布局几何"的属性：`width`/`height`、`margin`/`padding`、`top`/`left`、`display`、`font-size`、`border` 等。`transform` 和 `opacity` 是例外——它们由合成器处理，**不触发 reflow**，所以动画优先用它们。性能注意点：批量改样式用 `class` 切换而不是逐个改内联样式；动画用 `transform`/`opacity` 而非 `top`/`left`；读布局尺寸（如 `offsetWidth`）和写布局样式交错会导致"强制同步布局"，应把读和写分开。

```css
/* ✅ 动画优先用 transform/opacity，不触发 reflow */
.box { transition: transform .3s, opacity .3s; }
.box:hover { transform: translateY(-4px); opacity: .8; }
```

> **面试官想听到的要点：** 至少说出"`transform`/`opacity` 不触发 reflow，动画优先用它们"，这是最高频的性能考点。

**这一关你真正在练的一件事：把"为什么"讲出来。** 上面 15 题的答案，绝大多数你能"看懂"，但面试要求你"讲出来"。讲不出来，往往不是嘴笨，是脑子里还缺一环因果——比如你记得"`1fr` 会撑破"，却说不清"因为 `fr` 的最小尺寸是 `min-content`"。**每题答案里的加粗词，就是那句你要能脱口而出的因果链。** 建议每道题先自己讲一遍、再看答案，讲不出来的地方，回头重读对应章节。

> 一句话记住它：**能讲出因果的才叫懂，能背出结论的只叫熟。**

## 第五关 · 项目实战（5 题）

这 5 题要真的动手写 HTML+CSS。**参考答案都在 `examples/answers/` 下（都是可双击打开的 HTML）**，但请先自己写，写完在浏览器里打开对效果。

> 关于验证：CSS 没有"报错"，只有"现象"。所以这 5 题的验收方式就是——**在浏览器里打开，肉眼看布局对不对**。答案文件里每一块都配了说明文字，你可以对照着确认"这里该是两栏""这里该居中""这里该 sticky"。
>
> 这 5 题的顺序也是刻意安排的：第 1 题只用 Grid，第 2 题 Grid 里嵌 Flex，第 3 题只用 Flex + 定位，第 4 题 Flex 的列布局 + 居中，第 5 题把 Grid、Flex、媒体查询全串起来。**做完第 5 题，你就用同一套工具链走完了"骨架 → 组件 → 响应式"的完整链路。**

### 第 1 题 · 后台管理骨架（Grid 圣杯布局）

**需求：**

1. 用 Grid + `grid-template-areas` 搭一个后台框架：顶栏 `header`、左侧栏 `sidebar`、主内容 `main`、底栏 `footer`。
2. `header` 和 `footer` 跨满整行；`sidebar` 固定 200px，`main` 占剩余宽度。
3. 页面高度撑满视口（`min-height: 100vh`），`main` 内部内容滚动，`header`/`sidebar`/`footer` 不动。
4. `sidebar` 和 `main` 之间用 `gap` 留间距，不要用子项的 `margin` 去凑。

**思路提示：** 先画"布局地图"再定列宽——`grid-template-columns: 200px 1fr`，`grid-template-areas` 写三行，`header` 和 `footer` 各占两格。

**参考答案：** [`../examples/answers/a1-后台骨架.html`](../examples/answers/a1-后台骨架.html)

**验收清单：**
- [ ] 头部和底部横跨整行
- [ ] 左侧 200px 固定，不随窗口宽度变化
- [ ] 只有主内容区域会滚动，其余部分固定
- [ ] 改 `grid-template-areas` 的字符串就能调整布局（不用动 HTML）

### 第 2 题 · 响应式卡片网格

**需求：**

1. 一排卡片，用 `repeat(auto-fill, minmax(200px, 1fr))` 实现**自适应列数**。
2. 卡片最小 200px，容器变窄自动减列、变宽自动加列，不需要写任何媒体查询。
3. 卡片之间用 `gap` 留间距。
4. 每张卡片内部有：标题、一段描述、一个按钮，按钮靠底部对齐（内部用 Flex 列布局）。

**思路提示：** 外层是"自适应列数"的 Grid，内层每张卡片是"纵向排列 + 按钮贴底"的 Flex——这题同时考你 Grid 和 Flex 的嵌套。

**参考答案：** [`../examples/answers/a2-响应式卡片网格.html`](../examples/answers/a2-响应式卡片网格.html)

**验收清单：**
- [ ] 拖动浏览器窗口宽度，卡片列数**自动增减**
- [ ] 每列始终不小于 200px
- [ ] 卡片间间距一致，首尾无多余空隙
- [ ] 同一行卡片等高，按钮对齐在同一水平线

### 第 3 题 · sticky 导航栏

**需求：**

1. 顶部一个导航栏，logo 在最左、菜单项在最右（用 Flex 的 `margin-left: auto` 或 `justify-content: space-between`）。
2. 导航栏用 `position: sticky` 粘在页面顶部。
3. 页面其余部分放足够高的内容，确保能滚出"粘住"的效果。
4. 导航栏自身的高度、左右内边距要合理，且背景色不透明，否则滚到底下内容会"透"出来。

**思路提示：** `sticky` 的两个必要条件——`top: 0` 阈值 + 父级不能有 `overflow: hidden`。菜单推到右侧用 `margin-left: auto`。

**参考答案：** [`../examples/answers/a3-sticky导航栏.html`](../examples/answers/a3-sticky导航栏.html)

**验收清单：**
- [ ] 往下滚，导航栏**粘在视口顶部**不动
- [ ] logo 在最左，菜单项在最右
- [ ] 内容从导航栏底下滚过去时，导航栏背景不透出内容

### 第 4 题 · 商品卡片 + 水平垂直居中

**需求：**

1. 一个固定尺寸的商品卡，内部有图、标题、价格、按钮。
2. 卡片用 Flex 做**内部垂直布局**（标题、价格、按钮从上到下排，按钮贴底）。
3. 整张卡片在页面里**水平垂直居中**（用 Flex 或 Grid 任一写法）。
4. 图片用固定高度的色块占位即可，不必放真实图片。

**思路提示：** 两个独立的"居中/对齐"问题——外层是"卡片在页面居中"，内层是"按钮在卡片里贴底"。别把两层混在一起。

**参考答案：** [`../examples/answers/a4-商品卡片居中.html`](../examples/answers/a4-商品卡片居中.html)

**验收清单：**
- [ ] 卡片在页面正中间（水平 + 垂直）
- [ ] 卡片内部按钮贴底，不管标题长短都不被顶走
- [ ] 价格和按钮在视觉上分离清晰

### 第 5 题 · 综合布局（Flex 嵌套 Grid + 媒体查询）

**需求：**

1. 一个"文章页"布局：顶部文章列表区（Grid 三列卡片）+ 底部一段横向排列的功能按钮（Flex）。
2. 小屏（< 768px）时，Grid 从三列变单列，用**移动优先 + `min-width`** 写。
3. 按钮区在窄屏允许换行（`flex-wrap`），宽屏一行排开。
4. 文章卡片内部用 Flex 排标题和摘要，摘要占剩余空间。

**思路提示：** 这是前四题的合体——Grid 定骨架、Flex 排细节、媒体查询做结构切换。先想清楚"默认（移动端）长什么样"，再用 `min-width` 往上加。

**参考答案：** [`../examples/answers/a5-综合布局.html`](../examples/answers/a5-综合布局.html)

**验收清单：**
- [ ] 缩到 768px 以下，卡片从三列变一列
- [ ] 按钮区窄屏换行、宽屏一行
- [ ] 默认样式是"移动端单列"（移动优先），而非先写桌面再往回改
- [ ] 卡片内部标题在上、摘要在下，布局稳定

- 想回头补：哪一关掉分最多，就回到本章「评分与自查标准」表里指的那几章重读，重点看每节的"一句话记住它"。

**写布局时的 5 条自查（每次交代码前过一遍）：**

1. 我要排的是"一行/一列"还是"行列网格"？——决定用 Flex 还是 Grid。
2. 我声明的是"容器里元素的关系"，还是"某个元素自己的位置"？——前者写容器属性，后者写子项属性。
3. 有没有元素会因为"默认值"被意外压缩/撑破（`flex-shrink: 1`、`fr` 的 `min-content`）？——该 `flex-shrink: 0` 或 `minmax(0, 1fr)` 的别漏。
4. 间距是用 `gap` 写的，还是用子项 `margin` 凑的？——优先 `gap`，能避开外边距合并。
5. 默认样式是不是"最小屏幕"（移动优先）？断点是不是 `min-width` 从小到大？——避免桌面优先往回改。

> 一句话记住它：**能自己写出来、还能讲明白为什么，才叫学会了。**
